# § 3.1.1. Flip-Flop Storage

This section specifies flip-flop storage from feedback gates to an addressable memory. An SR latch leads to a gated D latch, an edge-triggered flip-flop, and a write-enabled cell. Cells form words, words form a storage bank, and address/control/read circuitry completes the memory device. These components store state; their outputs depend on earlier inputs as well as the current inputs.

The word, bank, and device here are memory components: a word has a write mask per byte and is reached through an address. The whole-word registers and state bits used by the RV32I circuitry are built from the same cell but are storage, not memory; they have no address or byte mask and are documented in [4.3.1](../rv32i/4.3/register.md#storage-and-memory).

| Component | Description | Structural | Behavioral |
| --- | --- | :---: | :---: |
| `SRLatch` | Holds one bit using active-low set and reset inputs | Yes | No |
| `GatedDLatch` | Follows a data input while enabled and holds it while disabled | Yes | No |
| `DFlipFlop` | Captures a data bit on the rising clock edge | Yes | No |
| `FlipFlopCell` | Adds write enable to a D flip-flop so a clock edge can either write or retain the stored bit | Yes | Yes |
| `FFWord<W>` | Stores one W-bit word with a write enable for each byte | Yes | Yes |
| `FFStorageBank<W>` | Groups a configurable number of words with shared data and separate word write enables | Yes | Yes |
| `FFMemory<W>` | Adds word addressing, access checks, and read selection to an FF storage bank | Yes | Yes |

These columns indicate actual simulator implementations; the simplified C++ examples below are not counted. Cells, words, banks, and complete FF memories each support structural and behavioral selection. Structural remains the default.

The [FF memory controller](3.3.md) connects this native device to the [shared transaction protocol](3.2.md). FF storage itself does not require a controller.

## Conventions

- Pin widths are listed in each table. FF memory words and banks use `W = 8, 16, 32`. `N` is the number of words. `0` and `1` are binary logic, `X` is unknown, and `Z` is high impedance. `Z` is not a third stored binary value; gates interpret it as unknown logic.
- `S_BAR` and `R_BAR` are active-low. The other components' `RST` is active-high and asynchronous: asserting it clears state without waiting for a clock edge, after gate propagation.
- State is not guaranteed to start at zero. Establish a known state with set/reset before relying on it. Every recorded scenario below starts with reset.
- Behavior tables describe settled outputs. A rising edge means `CLK` changes from `0` to `1`; a sustained high level is not another edge. Keep data and control inputs stable around the edge and allow propagation to finish.
- These are digital timing models, not analog metastability or transistor-voltage models. Their delays are simulator units, not calibrated device timings.

The simplified **C++ examples** describe binary behavior, not the simulator implementation. They assume reset has already established zero storage and, for clocked components, `CLK = 0`. Call `update` for each input change, including falling clock edges. They omit propagation delays and `X`/`Z` handling and can be compiled together in the order shown.

Each examples table contains **every recorded checkpoint** of its embedded scenario, with a zero-based number, the timeline label, and the absolute simulator time. Inputs are the values in effect at that checkpoint, including retained values. Preparation actions between checkpoints are replayed by the simulator; a table is not a sequence of independent truth-table inputs. Each component has its own standalone scenario, including the bank.

## 3.1.1.1. `SRLatch`

`SRLatch` stores one bit using feedback between two NAND gates. It has no clock or data input: set and reset directly select the stored state.

### IO pins

| Pin | Direction | Width | Description |
| --- | --- | ---: | --- |
| `S_BAR` | Input | 1 | Active-low set: requests `Q = 1` |
| `R_BAR` | Input | 1 | Active-low reset: requests `Q = 0` |
| `Q` | Output | 1 | Stored bit |
| `Q_BAR` | Output | 1 | Complement of `Q` in a valid, settled state |

### Behavior

| `S_BAR` | `R_BAR` | Settled `Q` | Settled `Q_BAR` | Operation |
| ---: | ---: | --- | --- | --- |
| 1 | 0 | 0 | 1 | Reset |
| 0 | 1 | 1 | 0 | Set |
| 1 | 1 | Previous `Q` | Previous `Q_BAR` | Hold a previously established valid state |
| 0 | 0 | 1 | 1 | Invalid storage condition: outputs are not complementary |

The invalid input pair does not produce a simulator exception: both NAND outputs settle to `1`. However, releasing both inputs together does not specify a reliable stored bit. The recorded scenario recovers by selecting reset explicitly. Do not use simultaneous release as a way to choose a state.

#### C++ example

```cpp
#include <stdexcept>

struct SRLatchReference {
    bool q = false;
    bool q_bar = true;

    void update(bool s_bar, bool r_bar) {
        if (!s_bar && !r_bar) {
            q = q_bar = true;  // Invalid storage condition.
        } else if (!s_bar) {
            q = true;
            q_bar = false;
        } else if (!r_bar) {
            q = false;
            q_bar = true;
        } else if (q == q_bar) {
            throw std::logic_error("Release from invalid state is unspecified");
        } // Otherwise hold the valid state.
    }
};
```

The exception is a guard in this example only. The simulator runs the actual NAND feedback circuit instead.

#### Unknown inputs and timing

The two NAND gates apply their normal four-state rules. Outputs are not automatically complementary during propagation, invalid input combinations, or unknown states. The recorded `high-z-set-input` checkpoint drives `S_BAR = Z` after a known reset state with `R_BAR = 1`; both outputs become `X`. `recover-from-high-z` demonstrates recovery through reset.

### Implementation

#### Structural implementation

| Internal component | Count | Connection |
| --- | ---: | --- |
| `NANDGate` | 2 | `NAND_Q` and `NAND_Q_BAR` feed each other's second input |

The feedback connections implement

$$
\begin{aligned}
Q &= \neg(S_{\mathrm{BAR}} \land Q_{\mathrm{BAR}}), \\
Q_{\mathrm{BAR}} &= \neg(R_{\mathrm{BAR}} \land Q).
\end{aligned}
$$

These are feedback equations, not two ordinary C++ assignments evaluated once. Gate events propagate until the circuit settles.

## 3.1.1.2. `GatedDLatch`

`GatedDLatch` adds a data input and an enable input to `SRLatch`. With `EN = 1`, it is transparent: changing `D` changes the stored value after propagation. With `EN = 0`, it holds its state.

### IO pins

| Pin | Direction | Width | Description |
| --- | --- | ---: | --- |
| `D` | Input | 1 | Data to store while enabled |
| `EN` | Input | 1 | Active-high transparency enable; not an edge-triggered clock |
| `RST` | Input | 1 | Active-high asynchronous reset |
| `Q` | Output | 1 | Stored bit |
| `Q_BAR` | Output | 1 | Complement of `Q` in a valid, settled state |

### Behavior

Here and below, “any” means either binary value, not an `X` input.

| `RST` | `EN` | `D` | Next settled `Q` |
| ---: | --- | --- | --- |
| 1 | Any | Any | 0 |
| 0 | 0 | Any | Previous `Q` |
| 0 | 1 | 0 | 0 |
| 0 | 1 | 1 | 1 |

Reset takes priority over enable and data. Releasing reset while `EN = 1` lets `D` propagate again; releasing it while disabled leaves the reset value stored.

#### C++ example

```cpp
struct GatedDLatchReference {
    bool q = false;

    void update(bool d, bool en, bool rst) {
        if (rst) q = false;
        else if (en) q = d;
    }

    bool q_bar() const { return !q; }
};
```

#### Unknown inputs and timing

The implementation evaluates the actual gates. For a known enabled latch with reset inactive, `D = X` or `D = Z` can make both outputs unknown. Asserting reset restores `Q = 0`, `Q_BAR = 1`, including after these unknown-data cases. The binary table does not specify every combination of unknown enable/reset inputs.

### Implementation

#### Structural implementation

| Internal component | Count | Function |
| --- | ---: | --- |
| `NOTGate` | 2 | Invert `D` and `RST` |
| `NANDGate` | 2 | Generate the active-low set/reset requests from `D` and `EN` |
| `ORGate` | 1 | Disable the set request while reset is asserted |
| `ANDGate` | 1 | Force the reset request active while reset is asserted |
| `SRLatch` | 1 | `STATE` holds the bit and supplies both outputs |

The inputs to `STATE` are

$$
\begin{aligned}
S_{\mathrm{BAR}} &= \neg(D \land EN) \lor RST, \\
R_{\mathrm{BAR}} &= \neg(\neg D \land EN) \land \neg RST.
\end{aligned}
$$

For settled binary inputs, the gating prevents data and enable from requesting set and reset simultaneously.

### Examples

<!-- simulator-examples: gated-d-latch GatedDLatchTest -->

`transparent-high` and `transparent-low` change `Q` while enable remains active. `disable` and `hold-low` show that a later change of `D` does not change the stored bit while disabled.

## 3.1.1.3. `DFlipFlop`

`DFlipFlop` combines two gated D latches to capture data on the rising clock edge. Unlike `GatedDLatch`, it does not keep following `D` throughout a high clock level.

### IO pins

| Pin | Direction | Width | Description |
| --- | --- | ---: | --- |
| `D` | Input | 1 | Data to capture on a rising edge |
| `CLK` | Input | 1 | Clock; capture occurs on `0 → 1` |
| `RST` | Input | 1 | Active-high asynchronous reset of both internal latches |
| `Q` | Output | 1 | Captured bit |
| `Q_BAR` | Output | 1 | Complement of `Q` in a valid, settled state |

### Behavior

| `RST` | Clock event | Next settled `Q` |
| ---: | --- | --- |
| 1 | Any or none | 0 |
| 0 | Rising edge | `D` prepared before the edge |
| 0 | Falling edge | Previous `Q` |
| 0 | No edge | Previous `Q` |

The component has no write-enable pin. Every valid rising edge captures data. Changing `D` while `CLK` stays high must not be treated as another write.

#### C++ example

```cpp
struct DFlipFlopReference {
    bool q = false;
    bool previous_clk = false;

    void update(bool d, bool clk, bool rst) {
        if (rst) q = false;
        else if (!previous_clk && clk) q = d;
        previous_clk = clk;
    }

    bool q_bar() const { return !q; }
};
```

#### Unknown inputs and timing

The recorded sequence captures `X` and `Z` data as unknown state and then recovers through reset. This does not establish analog setup/hold limits or define every ambiguous clock transition. Preparing data, allowing it to settle with `CLK = 0`, and then raising the clock is the sequence used by the tests.

### Implementation

#### Structural implementation

| Internal component | Count | Function |
| --- | ---: | --- |
| `NOTGate` | 1 | `NOT_CLK` produces the master's enable |
| `GatedDLatch` | 2 | `MASTER` receives `D`; `SLAVE` receives `MASTER.Q` and drives the outputs |

- While `CLK = 0`, `MASTER` is enabled and `SLAVE` holds its output.
- At the rising edge, `MASTER` closes and `SLAVE` opens, transferring the prepared value to `Q`.
- While `CLK = 1`, `MASTER` holds its value, so later input changes do not pass through to `Q`.
- At the falling edge, `SLAVE` closes and `MASTER` starts preparing the next value.

`RST` connects to both latches. The clock inverter and latch gates have propagation delays; this is a structural digital model, not an ideal zero-delay edge detector.

### Examples

`capture-one` records a rising-edge capture. `ignore-high-data-change` and `falling-edge` retain that value. Only `capture-zero`, the next rising edge, changes `Q` to the prepared zero.

## 3.1.1.4. `FlipFlopCell`

`FlipFlopCell` is a one-bit, write-enabled register. It combines `DFlipFlop` with a multiplexer that chooses between new data and the currently stored bit. `FFWord<W>` groups these cells into independently enabled byte lanes.

### IO pins

| Pin | Direction | Width | Description |
| --- | --- | ---: | --- |
| `D` | Input | 1 | New data to capture when writing |
| `WE` | Input | 1 | Active-high write enable |
| `CLK` | Input | 1 | Clock; an enabled write occurs on `0 → 1` |
| `RST` | Input | 1 | Active-high asynchronous reset |
| `Q` | Output | 1 | Stored bit; this component does not expose `Q_BAR` |

### Behavior

| `RST` | Clock event | `WE` | Next settled `Q` |
| ---: | --- | --- | --- |
| 1 | Any or none | Any | 0 |
| 0 | Rising edge | 1 | `D` prepared before the edge |
| 0 | Rising edge | 0 | Previous `Q` |
| 0 | No rising edge | Any | Previous `Q` |

Reset has priority over writing. `WE = 1` alone does not write: a rising edge is also required. The cell has no address input, read enable, refresh operation, or completion signal. Its stored value is continuously available at `Q`, subject to propagation delays.

#### C++ example

```cpp
struct FlipFlopCellReference {
    bool q = false;
    bool previous_clk = false;

    void update(bool d, bool we, bool clk, bool rst) {
        if (rst) q = false;
        else if (!previous_clk && clk && we) q = d;
        previous_clk = clk;
    }
};
```

#### Unknown inputs and timing

The recorded contract includes the following cases in both registered implementations:

- An enabled rising edge captures `D = X` or `D = Z` as `Q = X`.
- Asserting reset recovers a known zero from unknown state.
- With a stored zero and no clock edge, an uncertain reset preserves zero in the tested sequence.
- On a rising edge with `WE = X`, a stored zero and `D = 0` preserve zero; a stored zero and `D = 1` produce unknown state.

These are tested sequences, not a claim of exhaustive equivalence for arbitrary unknown clocks, simultaneous input changes, or all four-state histories. The behavioral form is timed from delay tables proven on the gates: never faster than them, sometimes slower.

### Implementation

#### Structural implementation

| Internal component | Count | Connection |
| --- | ---: | --- |
| `Mux2to1` | 1 | `WRITE_MUX.A = STATE.Q`, `WRITE_MUX.B = D`, `WRITE_MUX.SEL = WE` |
| `DFlipFlop` | 1 | `STATE.D = WRITE_MUX.OUT`; receives `CLK` and `RST`; drives `Q` |

For binary inputs, the data presented to the internal flip-flop is

$$
D_{\mathrm{STATE}} =
\begin{cases}
Q, & WE = 0, \\
D, & WE = 1.
\end{cases}
$$

The clock is not gated by `WE`. The flip-flop still captures on a disabled rising edge, but it captures its own previous value through the feedback path.

#### Behavioral implementation

[`FlipFlopCellBehavioral`](https://github.com/arnold518/reinventing-the-wheel/blob/github-pages/src/modules/memory/FlipFlopCellBehavioral.cpp) stores one `LogicValue` and the preceding clock value, both initially unknown. It retains the `FlipFlopCell` public type and pins, contains no internal gates, and schedules `Q` with one abstract delay tick.

Each evaluation gives reset priority. With reset low, a known `CLK = 0 → 1` transition captures `D` when `WE = 1` and retains the stored value when `WE = 0`. Captured `X` or `Z` becomes `X`. On that edge, an unknown write enable follows the structural AND/OR feedback mux: only an old zero and a new zero preserve zero; every other combination produces `X`, including two ones. An unknown reset merges the stored value with zero. The evaluator remembers the current clock after every evaluation.

`FlipFlopCellTest` runs the same state sequence against the structural and behavioral implementations and compares their checkpoint outputs. This validates the recorded sequences, not every possible four-state history. Checkpoint times can differ, so the table below describes the default structural run.

## 3.1.1.5. `FFWord<W>`

`FFWord<W>` stores one word using `W` instances of `FlipFlopCell`. All cells share the clock and reset. Byte write enables decide which groups of eight cells capture new data. There is no address input because this component stores only one word.

### IO pins

| Pin | Direction | Width | Description |
| --- | --- | ---: | --- |
| `WRITE_DATA` | Input | W | New word; bits 7:0 are the lowest byte |
| `WRITE_MASK` | Input | W/8 | Bit b enables writing byte b |
| `WE` | Input | 1 | Enables the masked write on a rising edge |
| `CLK` | Input | 1 | Rising-edge write clock |
| `RST` | Input | 1 | Active-high asynchronous clear of every bit |
| `Q` | Output | W | Continuously available stored word |

### Behavior

For byte b, the cell write enable is `WE AND WRITE_MASK[b]`.

| Condition | Next stored byte b |
| --- | --- |
| `RST = 1` | Zero, regardless of clock, mask, or `WE` |
| `RST = 0`, rising edge, `WE = 1`, mask bit b = 1 | Byte b of `WRITE_DATA` |
| Otherwise | Previous byte b |

`WRITE_MASK = 0` preserves the whole word. A high clock level is not another edge. For `FFWord<32>`, mask `0b0101` updates bytes 0 and 2 and retains bytes 1 and 3. Masking never packs or shifts the input bytes.

#### C++ example

```cpp
#include <cstddef>
#include <cstdint>

template<std::size_t W>
struct FFWordReference {
    static_assert(W == 8 || W == 16 || W == 32);
    std::uint32_t q = 0;
    bool previous_clk = false;

    void update(std::uint32_t data, std::uint8_t mask,
                bool we, bool clk, bool rst) {
        if (rst) q = 0;
        else if (!previous_clk && clk && we) {
            for (std::size_t b = 0; b < W / 8; ++b) {
                const auto lane = std::uint32_t{0xff} << (8 * b);
                if (mask & (1u << b))
                    q = (q & ~lane) | (data & lane);
            }
        }
        previous_clk = clk;
    }
};
```

Only the lowest W data bits and W/8 mask bits participate, matching the hardware pin widths. Unlike the simulator's unknown power-up state, this binary example starts after reset.

#### Unknown inputs and timing

Structural words inherit each cell's unknown-state behavior and gate delays. The behavioral word also starts unknown and stores captured `X`/`Z` data as `X`. Reset restores known zero. `FFWordContractTest` checks unknown startup and captured unknown data as well as binary operation.

The structural/behavioral equivalence guarantee is for known-binary controls at settled checkpoints, with data and mask prepared before the edge. It does not promise identical transients or exhaustive agreement for uncertain clocks and controls.

### Implementation

#### Structural implementation

| Internal component | Count | Responsibility |
| --- | ---: | --- |
| `BitSplitter<W>` | 1 | `DATA` exposes individual write-data bits |
| `BitSplitter<W/8>` | 1 | `MASK` exposes byte enable bits |
| `ANDGate` | W/8 | `BYTE_b` combines each mask bit with `WE` |
| `FlipFlopCell` | W | `CELL_b` stores each bit; created through its selectable family |
| `BitJoiner<W>` | 1 | `OUTPUT` packs the stored bits into `Q` |
| `ConstantValue<1>` | 1 | `ZERO` is a retained compatibility node; it does not drive FF storage |

Input splitters have their existing one-tick delay. Output packing is zero-delay wiring. This grouping adds no pipeline stage. Structural words may contain behavioral cells without changing the word's pins.

#### Behavioral implementation

[`FFWordBehavioral<W>`](https://github.com/arnold518/reinventing-the-wheel/blob/github-pages/src/modules/memory/FFWordBehavioral.hpp) stores W logic values and the previous clock, initially unknown. Reset clears all bits; an enabled known rising edge replaces the enabled byte lanes. It schedules `Q` with one abstract delay tick and has no child cells.

When neither the write enable nor the byte mask definitely disables a lane, an ambiguous enable follows the cell's AND/OR feedback mux: only old zero/new zero stays zero; every other combination becomes `X`. Unknown reset merges each stored bit with zero. Equivalence is checked at settled checkpoints, not during gate propagation.

### Examples

## 3.1.1.6. `FFStorageBank<W>`

`FFStorageBank<W>` groups N words. It distributes common write data, byte mask, clock, and reset, while keeping a separate write enable and output for each word. It does not decode an address, choose a read word, or implement a bus protocol. Here, “bank” is a storage grouping, not a DRAM command/timing model.

### IO pins

| Pin | Direction | Width | Description |
| --- | --- | ---: | --- |
| `WRITE_DATA` | Input | W | Shared data presented to every word |
| `WRITE_MASK` | Input | W/8 | Shared byte write mask |
| `CLK` | Input | 1 | Shared rising-edge write clock |
| `RST` | Input | 1 | Asynchronously clears every word |
| `WRITE_n` | Input | 1 each | Write enable for word n, for n = 0 through N−1 |
| `WORD_n` | Output | W each | Current contents of word n, for n = 0 through N−1 |

N is a construction-time word count, not another template parameter. The family accepts `depth_words` (default 4), with `1 <= N <= 4096 / W` in both implementations. Structural storage creates exactly N words, including for non-power-of-two depths. The behavioral bank removes those child components but retains every `WRITE_n` and `WORD_n` pin; it is not an unlimited-capacity addressable memory.

### Behavior

Each word follows §3.1.1.5 with `WE = WRITE_n`. A rising edge updates the enabled byte lanes of every word whose `WRITE_n = 1`; all other lanes hold. All `WORD_n` outputs are continuously available.

The bank does **not** enforce a one-hot write selection. Multiple high enables would write the same input data to multiple words. In `FFMemory`, address decoding and access control produce at most one high word enable for a known valid address. Reset clears every word regardless of those enables.

#### C++ example

```cpp
#include <vector>

template<std::size_t W>
struct FFStorageBankReference {
    std::vector<FFWordReference<W>> words;

    explicit FFStorageBankReference(std::size_t count) {
        if (count == 0 || count > 4096 / W)
            throw std::invalid_argument("Invalid bank depth");
        words.resize(count);
    }

    void update(std::uint32_t data, std::uint8_t mask,
                const std::vector<bool>& write, bool clk, bool rst) {
        if (write.size() != words.size())
            throw std::invalid_argument("One write enable per word required");
        for (std::size_t n = 0; n < words.size(); ++n)
            words[n].update(data, mask, write[n], clk, rst);
    }
};
```

`words[n].q` corresponds to `WORD_n`. The exceptions guard construction and the example's vector representation; the simulator exposes a fixed set of pins after construction.

#### Unknown inputs and timing

The structural bank adds no scheduling algorithm of its own: unknown-state behavior and capture timing belong to its words and their selected implementations. Common clock/reset fan out to all words. The behavioral bank starts with unknown bits and clock, captures `X`/`Z` data as `X`, and schedules its outputs with one abstract delay tick.

Equivalence is defined for settled checkpoints with known-binary controls and data/masks/enables prepared before the rising edge. Tests also cover unknown startup, selected-word `X` capture, unselected-word retention, and reset recovery. They do not establish identical gate transients or exhaustive equivalence for uncertain clocks and controls.

### Implementation

#### Structural implementation

| Internal component | Count | Responsibility |
| --- | ---: | --- |
| `FFWord<W>` | N | `WORD_0` through `WORD_(N−1)` hold the words |

Each child receives the shared inputs, its own `WRITE_n`, and drives its matching output. Words are created through their registered family, so each word can be structural or behavioral.

#### Behavioral implementation

[`FFStorageBankBehavioral<W>`](https://github.com/arnold518/reinventing-the-wheel/blob/github-pages/src/modules/memory/FFStorageBankBehavioral.hpp) stores N arrays of W logic values and one previous clock value, without child components. On a known rising edge it independently applies each word's enable and the shared byte mask. Multiple enabled words capture the same positioned data; the implementation does not reduce the enable pins to a single selected index.

Its uncertain-control rules match the behavioral word: for a lane that is not definitely disabled, ambiguous write enables or mask bits preserve zero only for old zero/new zero, following the cell's gate mux. Other combinations become `X`. Unknown reset merges stored bits with zero. A definite reset clears every word regardless of enable or mask.

The registered contract is `memory.ff.bank.W`. Its pin schema is generated from `depth_words`, so construction validates all N enables and outputs for both implementations. Selecting behavioral fidelity for `FFMemory.STORAGE` hides only the bank's words and cells; `ADDRESS_DECODE`, `ACCESS_CONTROL`, and `READ_SELECT` remain structural and visible.

### Examples

The embedded bank has **three 16-bit words**. Its 134 checkpoints cover all eight word-enable combinations and all four byte masks, followed by reset checks. Every `WORD_n` is an asserted root output, including words that should retain their old contents.

In a label such as `select-5-mask-1-write-edge`, `select-5` means binary `101`: `WRITE_0` and `WRITE_2` are high, while `WRITE_1` is low. Mask `01` updates only the low byte of words 0 and 2. Word 1 and the upper bytes retain their previous values. Selection 0 writes nothing; selection 7 enables all three words; mask 0 writes no bytes even when words are enabled.

Each selection/mask pair has four checkpoints: `setup` prepares inputs with a low clock, `write-edge` captures enabled bytes, `high-is-not-edge` changes the data without another capture, and `falling-is-not-write` lowers the clock without writing. The final four checkpoints check asynchronous reset, reset priority at an edge, release without an edge, and another reset.

## 3.1.1.7. `FFMemory<W>`

`FFMemory<W>` is the complete addressable FF device. It adds one shared word address, access checking, and a read multiplexer to `FFStorageBank<W>`. The structural implementation exposes those blocks; the behavioral implementation keeps the same device pins without expanding words or cells. Its decoder and read selector reuse the gate-construction routines described in [3.1.0. Helper Components](3.1.0.md#reuse-boundaries), without changing their FF-specific pins, range checks, or zero-on-disabled-read behavior.

### IO pins

| Pin | Direction | Width | Description |
| --- | --- | ---: | --- |
| `WORD_ADDR` | Input | 32 | Word index, not a byte address |
| `WRITE_DATA` | Input | W | Positioned bytes to write into the selected word |
| `WRITE_MASK` | Input | W/8 | Bit b enables byte b of that word |
| `WE` | Input | 1 | Enables writing on a rising clock edge |
| `READ_EN` | Input | 1 | Enables the asynchronous read output |
| `CLK` | Input | 1 | Rising-edge write clock |
| `RST` | Input | 1 | Active-high asynchronous clear of all stored words |
| `READ_DATA` | Output | W | Selected word, or zero for a disabled/known invalid read |
| `FAULT` | Output | 1 | Active read/write address is outside the configured depth |

There is no `READY` pin or request/response handshake. The caller must allow propagation to settle. Reads and writes use the same address.

### Behavior

For known binary controls, let `in_range = WORD_ADDR < depth_words`.

| Operation | Result |
| --- | --- |
| `READ_EN = 0` | `READ_DATA = 0`; contents are unchanged by disabling reads |
| `READ_EN = 1`, in range | `READ_DATA` follows the selected stored word after propagation, without a clock edge |
| `READ_EN = 1`, out of range | `READ_DATA = 0`, `FAULT = 1` |
| Rising edge, `WE = 1`, in range, `RST = 0` | Write the mask-enabled bytes of the selected word |
| `WE = 1`, out of range | No word is written; `FAULT = 1`, even before an edge |
| `READ_EN = WE = 0` | `FAULT = 0`, regardless of address |
| `RST = 1` | Clear all words; address/read/fault logic still follows its inputs |

In particular, `FAULT = (READ_EN OR WE) AND NOT in_range`; a zero write mask does not exempt an active invalid address. A valid simultaneous read/write observes the old word before the edge and the updated word after propagation. Reset is a storage clear, not an instruction to force `READ_EN`, `WE`, or `FAULT` low.

Width is fixed by `FFMemory<W>`; depth is supplied through `MemoryConfig`. For example, `FFMemory<32>` with `.depth_words = 4` stores **16 bytes**, while `FFMemory<8>` with the same depth stores **4 bytes**. Word index 2 identifies the third word in both; its byte offset is `2 * W/8`.

| Configuration | Meaning and limits |
| --- | --- |
| `depth_words` | N words; default 4. Non-power-of-two depths are supported. Structural expansion is limited to 4096 cells: at most 512/256/128 words for W = 8/16/32 |
| `read_delay_ticks` | Behavioral output delay in simulator ticks, not CPU cycles, for a device built without a proven delay table. Devices built through the catalog use the table proven on their gates instead. Default 1; structural selection requires 1 but retains its actual gate propagation delays |
| `initial_value` | Default unknown. Structural selection requires unknown startup; behavioral storage also supports configured initial fill |
| `record_history` | Controls behavioral backing-store history, not the simulator's separate wire/pin history |

Larger memories use the behavioral device rather than expanding every cell. This is a simulator resource limit, not a physical FF capacity claim.

#### C++ example

```cpp
template<std::size_t W>
struct FFMemoryReference {
    FFStorageBankReference<W> storage;
    std::uint32_t read_data = 0;
    bool fault = false;

    explicit FFMemoryReference(std::size_t count) : storage(count) {}

    void update(std::uint32_t address, std::uint32_t data,
                std::uint8_t mask, bool we, bool read_en,
                bool clk, bool rst) {
        const bool valid = address < storage.words.size();
        std::vector<bool> write(storage.words.size(), false);
        if (valid && we) write[address] = true;
        storage.update(data, mask, write, clk, rst);
        read_data = read_en && valid ? storage.words[address].q : 0;
        fault = (read_en || we) && !valid;
    }
};
```

This example exposes the binary composition: decode one write enable, update the bank, then select the read result. It uses the preceding small bank's depth guard. The scalable simulator implementation does not allocate this vector of word components.

#### Unknown inputs and timing

Unwritten storage is initially `X`; asserting reset establishes zero. Gate-level propagation determines structural intermediate values. The behavioral device suppresses writes with ambiguous controls, address, or mask; an unknown read enable or enabled unknown address produces unknown read data. Ambiguous active access controls/address/mask can produce unknown `FAULT`. Captured `Z` is stored as `X`; an unknown reset makes the behavioral storage unknown.

The shared equivalence contract is settled binary behavior, not all four-state histories. Output delays follow one rule: the behavioral device publishes after the delay proven on the structural device (its decoder, controls, cells, and read muxes), never earlier than those gates; `read_delay_ticks` applies only without such a table. Keep write address, data, mask, and `WE` stable before the capture edge.

### Implementation

#### Structural implementation

<!-- diagram: ff-memory -->

| Block | Inputs → outputs | Responsibility |
| --- | --- | --- |
| `MemoryAddressDecoder` | `WORD_ADDR` → `IN_RANGE`, `VALID_n`, `SELECT_b` | Validate the full 32-bit index, identify each valid word, and supply read-mux address bits |
| `MemoryAccessControl` | `IN_RANGE`, `VALID_n`, `WE`, `READ_EN` → `WRITE_n`, `READ_VALID`, `FAULT` | Gate each word write enable, permit valid reads, and flag active out-of-range accesses |
| `FFStorageBank<W>` | Shared data/mask/clock/reset and `WRITE_n` → `WORD_n` | Hold exactly N words as specified in §3.1.1.6 |
| `MemoryReadSelector<W>` | `WORD_n`, `SELECT_b`, `READ_VALID` → `READ_DATA` | Select the addressed word through mux trees and gate the result |

The decoder checks high address bits as well as the bits used for selection: an invalid index must not alias a valid word. Non-power-of-two depths have no extra storage cells; missing read-mux leaves are zero. A one-word device needs range checking but no word-selection decoder gates or read-selection muxes. These three address/control/read helper blocks are structural only; the bank's word/cell children remain selectable.

#### Behavioral implementation

[`FFMemoryBehavioral<W>`](https://github.com/arnold518/reinventing-the-wheel/blob/github-pages/src/modules/memory/FFMemoryBehavioral.hpp) implements the compact FF device. It uses `MemoryStorage` for values, known-bit masks, optional history, and setup-time image loading. Writes occur on rising edges and reset clears storage. The public display type remains `FFMemory8`, `FFMemory16`, or `FFMemory32`.

`MemoryContainer` is the implementation and `MemoryStorage` is its host-side backing store; they are **not extra hardware layers inside the structural bank**. Image loading and backing-store inspection are available on the behavioral device. The structural device instead exposes its actual word/cell pins.

Fidelity can be selected at four boundaries: the whole device, its bank, individual words, or individual cells. `FFMemoryFidelityTest` compares these combinations at settled checkpoints. Collapsing a parent removes its visible children; saved child choices remain available when structural expansion is restored.
