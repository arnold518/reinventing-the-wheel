# § 3.3. Memory Controllers

Controllers translate [memory transactions](3.2.md) into the different native interfaces in [3.1](3.1/index.md). They own request/response state, not memory contents. A complete endpoint connects a controller to a separate memory device.

| Component | Description | Structural | Behavioral |
| --- | --- | :---: | :---: |
| `MemoryController<T,W>` | Shared transaction registers plus a technology-specific timed sequencer | Yes | No |
| `MemoryEndpoint<T,W>` | Controller plus device; interchangeable with a compact MemoryContainer at the transaction boundary | Yes | Yes |

T is `ff`, `sram`, `dram`, `rom`, `nor-flash`, or `container`; W is 8, 16, or 32. Angle brackets describe dimensions in visualizer labels; the C++ controller/endpoint constructors take width and technology as arguments. The `container` relay endpoint has only the assembled implementation; its attached container is already behavioral.

## Configuration

Controller and native device must agree on depth, row/block geometry, and timing. `MemoryEndpoint` constructs matching pairs. Standalone-controller users must connect a device with the same configuration.

| Parameter | Default | Meaning |
| --- | ---: | --- |
| `depth_words` | 4 | Addressable words; capacity is N×W/8 bytes |
| `words_per_row` | 2 | Matrix words per row; 1/2/4/8/16 dividing N |
| `block_words` | 2 | NOR erase block; whole rows dividing N |
| `phase_ticks` | 32 | Native device phase spacing |
| `guard_ticks` | 64 | Setup/recovery interval around native command strobes; minimum 64 |
| `program_ticks`, `erase_ticks` | 128, 256 | NOR operation intervals |
| `retention_ticks` | 1,000,000,000 | DRAM closed-row retention interval |
| `refresh_interval_ticks` | 10,000 | Controller refresh-start target; 0 deliberately disables refresh |
| `image_hex` | Empty | ROM construction-time image; unspecified tail is zero |

Capacity must be nonzero and fit below 2^32 bytes. Matrix geometry applies to SRAM/DRAM/ROM/NOR, and block geometry only to NOR. Accepted timing ranges are 32…10,000 for phase ticks, 64…1,000,000 for guards, phase…1,000,000 for programming, program…10,000,000 for erase, and 1,024…1,000,000,000 for DRAM retention. Refresh configuration must additionally meet the retention coverage check below. Unsupported values are rejected during construction.

Expanded endpoint storage is limited to 4,096 cells. Standalone controllers do not allocate those cells. The universal interface does not make native SRAM/ROM suddenly clocked: their controller is clocked, while their access pins remain asynchronous. Device command strobes are generated with explicit setup/recovery guards; this is a digital simulator controller, not a calibrated DDR PHY.

## 3.3.1. `MemoryController<T,W>`

Connects a requester to an external native device, or buffers another transaction endpoint.

### IO pins

The requester side is exactly the [common protocol](3.2.md#io-pins): CLK/RST, REQ_VALID/READY, REQ_OP, REQ_ADDR, REQ_WRITE_DATA/MASK, RSP_VALID/READY, RSP_READ_DATA/STATUS. Backend-only START/DONE pins are internal, not part of this component's public interface.

Native pin names have a `MEM_` prefix. Directions below are relative to the controller.

| Technology | Controller outputs → device inputs | Device outputs → controller inputs |
| --- | --- | --- |
| FF | `MEM_WORD_ADDR<32>`, `MEM_WRITE_DATA<W>`, `MEM_WRITE_MASK<W/8>`, `MEM_CLK`, `MEM_RST`, `MEM_WE`, `MEM_READ_EN` | `MEM_READ_DATA<W>`, `MEM_FAULT` |
| SRAM | `MEM_WORD_ADDR<32>`, `MEM_WRITE_DATA<W>`, `MEM_WRITE_MASK<W/8>`, `MEM_CE_N`, `MEM_WE_N`, `MEM_OE_N` | `MEM_READ_DATA<W>` |
| ROM | `MEM_WORD_ADDR<32>`, `MEM_CE_N`, `MEM_OE_N` | `MEM_READ_DATA<W>` |
| DRAM | `MEM_ADDR<32>`, `MEM_WRITE_DATA<W>`, `MEM_WRITE_MASK<W/8>`, `MEM_CLK`, `MEM_CMD<3>` | `MEM_READ_DATA<W>`, `MEM_BUSY`, `MEM_ERROR`, `MEM_READ_VALID` |
| NOR flash | `MEM_WORD_ADDR<32>`, `MEM_WRITE_DATA<W>`, `MEM_WRITE_MASK<W/8>`, `MEM_CLK`, `MEM_CMD<3>` | `MEM_READ_DATA<W>`, `MEM_BUSY`, `MEM_ERROR`, `MEM_READ_VALID` |
| Container | `MEM_CLK`, `MEM_RST`, `MEM_REQ_VALID`, `MEM_REQ_OP<3>`, `MEM_REQ_ADDR<32>`, `MEM_REQ_WRITE_DATA<W>`, `MEM_REQ_WRITE_MASK<W/8>`, `MEM_RSP_READY` | `MEM_REQ_READY`, `MEM_RSP_VALID`, `MEM_RSP_READ_DATA<W>`, `MEM_RSP_STATUS<3>` |

Unannotated controls/status pins are one bit. Native FF reset is held low: protocol reset does not clear its storage. The container relay forwards the bus clock. While idle, it forwards reset to initialize the downstream transaction state (including structural endpoint flip-flops). Once an operation is launched, it drains the downstream response without resetting that endpoint midway through the operation; the upstream reset suppresses the abandoned response but does not undo an accepted write.

### Behavior

Request fields are latched, validated, then translated once. Invalid requests never issue native operations. Results are captured before native pins are released and are held independently of subsequent device activity.

| Technology | Access sequence |
| --- | --- |
| FF | Establish address/data → enable read/write → pulse native CLK → capture result/fault → release |
| SRAM | Select CE/WE/OE and stable payload → wait four native phases plus guards → capture/release |
| ROM | Select address/output → wait settling interval → capture/release; reject modifications |
| DRAM | Reuse matching open row; otherwise PRECHARGE if needed, ACTIVATE row, READ/WRITE slot; wait for completion |
| NOR flash | READ, or WREN followed by PROGRAM/ERASE; wait BUSY, check ERROR and read-valid |
| Container | Forward one latched transaction; wait for downstream handshake and response; add buffering, not device latency |

DRAM refresh is serviced when the bus clock runs, including while a response is held under backpressure. It closes an open row before issuing REFRESH. Configuration rejects a refresh schedule that cannot cover all rows within retention, including a conservative access-service allowance. Stopping the bus clock also stops starting maintenance; data can expire. REFRESH cannot recover already lost data. Timing experiments with refresh disabled must use finite simulation windows and expect retention effects.

#### C++ example

The controller combines the `Port<W>` reference from [3.2](3.2.md#c-example) with the explicit `Sequence` reference below. It owns **no device and no backing storage**. Request validation, native pin generation, command queues, refresh, error handling, reset draining, and container relaying are shown here; no production sequencer is called. The caller supplies device feedback through `read_native` and connects `native_pins()` to a separate device.

`Sequence` and `Controller` below are documentation-only reference classes, not registered components. Paste 3.2 before this excerpt. Only the project's value/configuration types and small signal/conversion helpers are reused (`Bits`, `Request`, `Signals`, `signal`, `high`, `bits`, `number`, `known`, and overflow-checked `after`). Pin dictionary keys omit the public `MEM_` prefix. Call at input changes and each nonzero deadline. One transition runs per deadline; a stopped bus clock does not stop an already scheduled native command, but does stop starting new refresh maintenance.

```cpp
// Requires memory_example::Port<W> from the 3.2 example.
#include "MemoryEndpointEngine.hpp"

namespace memory_example {
class Sequence {
    enum class Phase { Idle, Setup, ClockHigh, Capture, StaticAccess,
                       CommandHigh, CommandLow, CommandWait, Release, RelayRequest, RelayResponse };
    struct Command { unsigned op; std::uint32_t address; };
    std::size_t width_, due_ = 0, next_refresh_ = 0, row_ = 0;
    Technology technology_;
    EndpointConfig config_;
    Phase phase_ = Phase::Idle;
    Request request_;
    std::deque<Command> commands_;
    bool aborted_ = false, maintenance_ = false, row_open_ = false;

    Status validate(const Request& r) const {
        if (!known(r.op) || !known(r.address)) return Status::InvalidRequest;
        const auto op = number(r.op), a = number(r.address);
        if (op > 3) return Status::Unsupported;
        if ((op == 1 || op == 2) && !known(r.mask)) return Status::InvalidRequest;
        if (a % (width_ / 8)) return Status::Alignment;
        if (a / (width_ / 8) >= config_.depth_words) return Status::Range;
        if (technology_ == Technology::Container) return Status::Ok;
        if (technology_ == Technology::ROM && op) return Status::ReadOnly;
        if (technology_ == Technology::NORFlash) {
            if (op == 1) return Status::Unsupported;
            if (op == 3 && (a / (width_ / 8)) % config_.block_words) return Status::Alignment;
        } else if (op > 1) return Status::Unsupported;
        return Status::Ok;
    }
    void idle() {
        for (auto p : {"CLK", "RST", "WE", "READ_EN", "REQ_VALID", "RSP_READY"}) outputs[p] = {L};
        for (auto p : {"CE_N", "WE_N", "OE_N"}) outputs[p] = {H};
        for (auto p : {"CMD", "REQ_OP"}) outputs[p] = bits(3, 0);
        for (auto p : {"ADDR", "WORD_ADDR", "REQ_ADDR"}) outputs[p] = bits(32, 0);
        outputs["WRITE_DATA"] = outputs["REQ_WRITE_DATA"] = Bits(width_, L);
        outputs["WRITE_MASK"] = outputs["REQ_WRITE_MASK"] = Bits(width_ / 8, L);
    }
    void finish(std::size_t t) {
        idle(); phase_ = Phase::Release; due_ = after(t, config_.guard_ticks);
    }
    void command(std::size_t t) {
        if (commands_.empty()) { finish(t); return; }
        outputs["CLK"] = {L}; outputs["CMD"] = bits(3, commands_.front().op);
        outputs["ADDR"] = outputs["WORD_ADDR"] = bits(32, commands_.front().address);
        phase_ = Phase::CommandHigh; due_ = after(t, config_.guard_ticks);
    }
public:
    bool done = false, available = true;
    Bits result;
    Status status = Status::Ok;
    Signals outputs;
    Sequence(std::size_t w, Technology technology, EndpointConfig config)
        : width_(w), technology_(technology), config_(config), result(w, L) { idle(); }
    std::size_t deadline() const { return due_; }
    void step(std::size_t t, bool edge, bool reset, bool start, const Request& request,
              const std::function<Bits(const std::string&, std::size_t)>& read) {
        if (reset) aborted_ = true; // Drain launched work; suppress its response.
        if (phase_ == Phase::Idle) {
            if (technology_ == Technology::Container) outputs["RST"] = {reset ? H : L};
            if (!start) done = false;
            if (reset) { available = false; return; }
            available = !done;
            if (done) return;
            const bool refresh = technology_ == Technology::DRAM && edge &&
                config_.refresh_interval_ticks && t >= next_refresh_;
            if (!start && !refresh) { aborted_ = false; return; }
            aborted_ = false; maintenance_ = refresh; available = false;
            status = Status::Ok; result.assign(width_, L); commands_.clear();
            if (refresh) { // Maintenance has priority; the captured request waits.
                if (row_open_) commands_.push_back({4, 0});
                commands_.push_back({5, 0});
                next_refresh_ = after(t, config_.refresh_interval_ticks);
                command(t); return;
            }
            request_ = request; status = validate(request);
            if (status != Status::Ok) { finish(t); return; }
            const auto op = number(request.op);
            const auto word = number(request.address) / (width_ / 8);
            outputs["WORD_ADDR"] = bits(32, word);
            outputs["WRITE_DATA"] = request.data; outputs["WRITE_MASK"] = request.mask;
            if (technology_ == Technology::Container) {
                outputs["REQ_ADDR"] = request.address; outputs["REQ_OP"] = request.op;
                outputs["REQ_WRITE_DATA"] = request.data; outputs["REQ_WRITE_MASK"] = request.mask;
                outputs["REQ_VALID"] = {H}; outputs["RSP_READY"] = {L};
                phase_ = Phase::RelayRequest; return;
            }
            if (technology_ == Technology::FF) {
                phase_ = Phase::Setup; due_ = after(t, config_.guard_ticks); return;
            }
            if (technology_ == Technology::SRAM || technology_ == Technology::ROM) {
                outputs["CE_N"] = {L}; outputs["WE_N"] = {op == 1 ? L : H};
                outputs["OE_N"] = {op == 0 ? L : H};
                phase_ = Phase::StaticAccess;
                due_ = after(t, 4 * config_.phase_ticks + 2 * config_.guard_ticks); return;
            }
            if (technology_ == Technology::DRAM) {
                const auto row = word / config_.words_per_row;
                if (row_open_ && row_ != row) commands_.push_back({4, 0});
                if (!row_open_ || row_ != row) commands_.push_back({1, std::uint32_t(row)});
                commands_.push_back({op == 0 ? 2u : 3u, std::uint32_t(word % config_.words_per_row)});
            } else {
                if (op) commands_.push_back({4, 0}); // WREN before either mutation.
                commands_.push_back({op == 0 ? 1u : op == 2 ? 2u : 3u, std::uint32_t(word)});
            }
            command(t); return;
        }
        available = false;
        if (phase_ == Phase::RelayRequest || phase_ == Phase::RelayResponse) {
            if (!edge) return;
            if (phase_ == Phase::RelayRequest && read("REQ_READY", 1) == Bits{H}) {
                outputs["REQ_VALID"] = {L}; outputs["RSP_READY"] = {H}; phase_ = Phase::RelayResponse;
            } else if (phase_ == Phase::RelayResponse && read("RSP_VALID", 1) == Bits{H}) {
                auto s = read("RSP_STATUS", 3);
                status = known(s) && number(s) <= 6 ? Status(number(s)) : Status::Device;
                result = read("RSP_READ_DATA", width_); finish(t);
            }
            return;
        }
        if (!due_ || t < due_) return;
        due_ = 0;
        switch (phase_) {
        case Phase::Setup:
            outputs["WE"] = {number(request_.op) == 1 ? H : L};
            outputs["READ_EN"] = {number(request_.op) == 0 ? H : L};
            phase_ = Phase::ClockHigh; due_ = after(t, config_.guard_ticks); break;
        case Phase::ClockHigh:
            outputs["CLK"] = {H}; phase_ = Phase::Capture; due_ = after(t, config_.guard_ticks); break;
        case Phase::Capture:
            if (read("FAULT", 1) != Bits{L}) status = Status::Device;
            if (number(request_.op) == 0) result = read("READ_DATA", width_);
            finish(t); break;
        case Phase::StaticAccess:
            if (number(request_.op) == 0) result = read("READ_DATA", width_);
            finish(t); break;
        case Phase::CommandHigh:
            outputs["CLK"] = {H}; phase_ = Phase::CommandLow; due_ = after(t, config_.guard_ticks); break;
        case Phase::CommandLow: {
            outputs["CLK"] = {L}; outputs["CMD"] = bits(3, 0);
            auto op = commands_.front().op;
            std::size_t wait = config_.phase_ticks;
            if (technology_ == Technology::DRAM) wait *= op == 5 ? 5 : op == 2 ? 1 : 3;
            else if (op == 2 || op == 3)
                wait = (op == 2 ? config_.program_ticks : config_.erase_ticks) + 2 * config_.phase_ticks;
            phase_ = Phase::CommandWait; due_ = after(t, wait + config_.guard_ticks); break;
        }
        case Phase::CommandWait: {
            if (read("BUSY", 1) != Bits{L}) { due_ = after(t, config_.guard_ticks); break; }
            if (read("ERROR", 1) != Bits{L}) { status = Status::Device; commands_.clear(); finish(t); break; }
            auto cmd = commands_.front(); commands_.pop_front();
            if (technology_ == Technology::DRAM) {
                if (cmd.op == 1) { row_open_ = true; row_ = cmd.address; }
                if (cmd.op == 4) row_open_ = false;
            }
            if ((technology_ == Technology::DRAM && cmd.op == 2) ||
                (technology_ == Technology::NORFlash && cmd.op == 1)) {
                if (read("READ_VALID", 1) != Bits{H}) status = Status::Device;
                else result = read("READ_DATA", width_);
            }
            command(t); break;
        }
        case Phase::Release:
            phase_ = Phase::Idle; done = !maintenance_ && !aborted_;
            available = !done && !reset; break;
        default: break;
        }
        if (status != Status::Ok) result.assign(width_, L);
    }
};

template<std::size_t W>
class Controller {
    static EndpointConfig checked(Technology technology, EndpointConfig config) {
        config.validate(W, technology);
        return config;
    }
    Technology technology_;
    Port<W> port_;
    Sequence sequence_;
    Signals pins_;
    bool previous_clock_ = false;
public:
    struct Inputs {
        bool clock = false, reset = false;
        bool request_valid = false, response_ready = false;
        Request request{bits(3, 0), bits(32, 0), Bits(W, L), Bits(W / 8, L)};
    };
    Controller(Technology technology, EndpointConfig config)
        : technology_(technology), sequence_(W, technology, checked(technology, config)),
          pins_(sequence_.outputs) {}

    const Signals& native_pins() const { return pins_; }
    std::size_t next_event_time() const { return sequence_.deadline(); }

    typename Port<W>::Outputs step(std::size_t time, const Inputs& in,
        const std::function<Bits(const std::string&, std::size_t)>& read_native) {
        const bool rising = !previous_clock_ && in.clock;
        previous_clock_ = in.clock;
        typename Port<W>::Inputs front;
        front.rising_edge = rising; front.reset = in.reset;
        front.request_valid = in.request_valid; front.response_ready = in.response_ready;
        front.request = in.request;
        front.backend_ready = sequence_.available; front.done = sequence_.done;
        front.result = sequence_.result; front.status = bits(3, unsigned(sequence_.status));
        auto out = port_.step(front);

        sequence_.step(time, rising, in.reset, out.start, out.request, read_native);
        pins_ = sequence_.outputs;
        if (technology_ == Technology::Container)
            pins_["CLK"] = {in.clock ? H : L}; // Relay uses the requester's clock.
        return port_.outputs(in.reset, sequence_.available);
    }
};
} // namespace memory_example
```

The port captures the request and holds the response; `NativeSequence` validates fields, maps byte addresses to native addresses, issues commands, and waits for device completion. For DRAM this includes row changes and refresh. For NOR it includes WREN, PROGRAM/ERASE, and BUSY/error handling. For `Technology::Container` it forwards transactions and the bus clock to another endpoint. There is no generic “one delayed array access” replacing these sequences.

Start with reset asserted and a known-low clock. Step at input changes, clock changes, and every sequencer/device deadline; settle the separate device before sampling its feedback, then update it with the new native outputs. `Signals` uses unprefixed native names (`CLK`, `CMD`, etc.); the actual controller exposes these as `MEM_*` pins. The returned view includes the frontend's internal START/payload for inspection; those are not additional public controller pins. Gate propagation and wire scheduling are omitted, not device timing or reset-draining policy.

The container relay needs **simultaneous clock-edge sampling**: snapshot downstream READY/VALID/data before the edge, clock the downstream endpoint with the old request/response controls, then update the controller using that snapshot and publish its new controls. Merely calling the two state machines in sequence with their newly updated handshake values can drop a transfer. The real circuit's separate `BUS_CLOCK` connection and event ordering provide this shared-clock behavior; the executable example harness models it explicitly.

This reference is not a registered behavioral controller. Tests execute it with separate FF/SRAM/DRAM/ROM/NOR models and a downstream container relay, including reset during programming. Invalid requests must not issue a native access for that request; independent DRAM refresh may still proceed.

#### Unknown inputs and timing

Handshake controls must be binary. Required unknown payload fields return INVALID_REQUEST; unknown read contents remain X and are not a readiness signal. Native BUSY/ERROR/READ_VALID must settle before completion. The controller does not guess completion from READ_DATA and has no implicit timeout that could cause a store to be retried twice. Clock setup/hold requirements and guards apply to structural paths. Reset suppresses response delivery but drains a launched sequence; it cannot roll back its side effects.

### Implementation

#### Structural implementation

`TRANSACTION` is the gate/FF-built frontend from 3.2. `DEVICE_CONTROL` is an explicitly named terminal **timed digital sequencer**, not an expanded gate-level FSM or analog model. It holds native command state and deadlines but no contents. This classification is intentional: the register/control boundary is visible, while technology access sequencing is a primitive, like the existing native device command controls.

## 3.3.2. `MemoryEndpoint<T,W>`

Assembly of `CONTROLLER` and `MEMORY`. Unlike a standalone controller, this component includes actual storage. The behavioral endpoint is [MemoryContainer](3.1.6.md), replacing both controller and device at this boundary, not replacing native device pins.

### IO pins

| Pin | Direction | Width | Description |
| --- | --- | ---: | --- |
| `CLK`, `RST`, `REQ_VALID`, `RSP_READY` | Input | 1 | Shared clock, interface reset, handshakes |
| `REQ_OP` | Input | 3 | Operation |
| `REQ_ADDR` | Input | 32 | Aligned byte address |
| `REQ_WRITE_DATA` | Input | W | Positioned data |
| `REQ_WRITE_MASK` | Input | W/8 | Byte enables |
| `REQ_READY`, `RSP_VALID` | Output | 1 | Request acceptance / response available |
| `RSP_READ_DATA` | Output | W | Result |
| `RSP_STATUS` | Output | 3 | Status |

### Behavior

The shared protocol and selected technology rules apply unchanged. Native addresses, enables and command status remain visible inside the assembled endpoint. For `T=container`, the example attaches an SRAM-model MemoryContainer to the buffering controller; a standalone container controller can attach to any endpoint with the same word width and port contract.

#### C++ example

The endpoint adds wiring and evaluation order, not another memory algorithm. This reference owns the preceding controller and a separately supplied device reference. `Device` provides `update(time,pins)`, `read(pin,width)`, and `deadline()`; the [3.1.6 `CompactDevice`](3.1.6.md#c-example) is one usable implementation. Both receive the same validated configuration. For a container relay, the device wrapper must translate its transaction inputs/outputs into these three methods.

The shared clock requires pre-edge feedback sampling: both controller and downstream endpoint observe the old handshake before either changes state. This also explains why merely calling one component after the other is insufficient for a relay. Call `step` on input changes and at the earliest reported deadline, as for the constituent references. The factory at the bottom shows how to construct the actual simulator component; it is separate from the reference algorithm.

```cpp
#include "components/Component.hpp"
#include "modules/memory/MemoryController.hpp"
#include <algorithm>
namespace memory_example {
template<std::size_t W, class Device>
struct Endpoint {
    Technology technology;
    Controller<W> controller;
    Device device;
    Endpoint(Technology t, EndpointConfig config)
        : technology(t), controller(t, config), device(config) {}
    auto step(std::size_t time, const typename Controller<W>::Inputs& in) {
        device.update(time, controller.native_pins());
        Signals sampled;
        if (technology == Technology::Container) {
            for (auto [pin, width] : std::vector<std::pair<std::string, std::size_t>>{
                    {"REQ_READY", 1}, {"RSP_VALID", 1}, {"RSP_READ_DATA", W}, {"RSP_STATUS", 3}})
                sampled[pin] = device.read(pin, width);
            auto clocked = controller.native_pins();
            clocked["CLK"] = {in.clock ? H : L};
            device.update(time, clocked);
        }
        auto out = controller.step(time, in, [&](const std::string& pin, std::size_t width) {
            return technology == Technology::Container ? signal(sampled, pin, width) : device.read(pin, width);
        });
        device.update(time, controller.native_pins());
        return out;
    }
    std::size_t next_event_time() const {
        auto a = controller.next_event_time(), b = device.deadline();
        return a == 0 ? b : b == 0 ? a : std::min(a, b);
    }
};
} // namespace memory_example

std::shared_ptr<MemoryEndpoint> make_sram_endpoint() {
    circuit::memory::EndpointConfig config;
    config.depth_words = 4;
    config.words_per_row = 2;
    return Component::create<MemoryEndpoint>("MEMORY", 8, circuit::memory::Technology::SRAM, config);
}
```

The example is executed by the documentation test, which checks both children and their connected native pins. Unlike `Controller` above, the returned endpoint owns actual storage. Select its behavioral implementation to replace the controller/device assembly with `MemoryContainer`; do not substitute a native SRAM device at the transaction pins.

#### Unknown inputs and timing

The endpoint adds no new transaction semantics. Structural and compact implementations agree at documented transaction checkpoints, not at every internal gate transition. Unknown data and error results follow 3.2. Model times are not calibrated hardware performance claims.

### Implementation

#### Structural implementation

Controller on the left, native device on the right. The device retains its existing word/row/column layout and family-specific pins. Native device children may independently select their existing behavioral implementations through the explorer.

#### Behavioral implementation

The five technology endpoints can instead use one MemoryContainer block. The relay example remains an explicit controller plus container rather than wrapping itself recursively. Compact storage can scale beyond the structural expansion limit.

### Source and tests

- [Assembly and native wiring: `MemoryController.cpp`](https://github.com/arnold518/reinventing-the-wheel/blob/github-pages/src/modules/memory/MemoryController.cpp)
- [Catalog: `MemoryEndpointCatalog.cpp`](https://github.com/arnold518/reinventing-the-wheel/blob/github-pages/src/modules/memory/MemoryEndpointCatalog.cpp)
- [All endpoint scenarios and contracts: `MemoryEndpointTests.cpp`](https://github.com/arnold518/reinventing-the-wheel/blob/github-pages/src/tests/MemoryEndpointTests.cpp)

`MemoryEndpointContractTest` compares all five technology endpoints at widths 8/16/32. `MemoryEndpointTimingTest` checks held responses, interface reset without storage clearing, reset during flash programming, refresh under backpressure, and retention loss after stopping the clock. RV32I integration is checked separately by `RV32IMemoryMigrationTest`: both CPU cores directly expose this common port and connect to either containers or small native-device endpoints. Neither integration nor these endpoint tests imply cache/coherence support.

[`MemoryEndpointIntegrationTest`](https://github.com/arnold518/reinventing-the-wheel/blob/github-pages/tests/MemoryEndpointIntegrationTest.py) also compiles the exact documentation snippets. Its [reference checks](https://github.com/arnold518/reinventing-the-wheel/blob/github-pages/tests/fixtures/memory/transaction-controller-examples.cpp) exercise all six controller/endpoint backends at W=8/16/32, and compare the documented sequencer's pins, result, status, availability, completion, and deadlines with the production sequencer over 432,000 deterministic steps. The endpoint reference itself is instantiated and exercised, not just syntax-checked.
