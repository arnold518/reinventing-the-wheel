# § 5.4.1. Registers

A device's registers are data: a **register table**. The same table builds
the device's register front end and the guest header's `#define`s. The
Markdown register maps on these pages describe those definitions; they are
currently maintained by hand, rather than generated by the site build.

| Component | Description | Structural | Behavioral |
| --- | --- | :---: | :---: |
| `DeviceRegisterPort<W>` | Takes one bus request, holds it, returns the answer the device gives | Yes | Yes (W = 32) |
| Register front end (`RegisterFrontEnd<…>`) | Decode, access checks, read selection, write strobes, read-write storage | Yes, inside each device | Compiled with the device |

## Register tables

Each row is one 32-bit register at a word offset.

| Field | Meaning |
| --- | --- |
| name | `TX`, `STATUS`, … ; the header calls it `<DEVICE>_<NAME>` |
| offset | A multiple of 4, below `0x80` |
| access | One of the five kinds below |
| bits | Significant width, 1–32; higher bits read as 0 |
| value | The constant of a setting; the current read-write registers all reset to zero |
| fields | Optional named bits, for the header (`BUTTONS_STATUS_VALID`) |

| Access | Read | Write | Example |
| --- | --- | --- | --- |
| read-only | The value the core supplies | ReadOnly (3) | `BUTTONS.COUNT` |
| setting | A constant fixed when the device is built | ReadOnly (3) | `DISPLAY.WIDTH` |
| read-write | The stored value | Stores it (it must fit the bits) | `LEDS.LEDS` |
| write-only data | Unsupported (4) | Hands the value to the core (it must fit the bits) | `CONSOLE.TX` |
| command | Unsupported (4) | Writing 1 acts once; 0 does nothing; anything else is Invalid (6) | `BUTTONS.POP` |

An offset with no register answers Range (2). A write whose value does not
fit its register (or has unknown bits) answers Invalid (6) and changes
nothing. These are checked in this order: no register, then read-only
written, then write-only read, then the value.

## 5.4.1.1. `DeviceRegisterPort<W>`

### IO pins

Catalog `device.word.register-port.W` supports W = 8, 16, 32; only W = 32
has a compact form. All register devices in this chapter use that width.

| Pin | Direction | Width | Meaning |
| --- | --- | ---: | --- |
| `CLK`, `RST` | Input | 1 each | Clock; reset discards a held request and answer |
| `REQ_VALID`, `REQ_OP`, `REQ_ADDR`, `REQ_WRITE_DATA`, `REQ_WRITE_MASK`, `RSP_READY` | Input | 1, 3, 32, W, W/8, 1 | The bus side: requests |
| `REQ_READY`, `RSP_VALID`, `RSP_READ_DATA`, `RSP_STATUS` | Output | 1, 1, W, 3 | The bus side: answers |
| `ADDRESS` | Output | 32 | The held request's offset |
| `IS_READ`, `IS_WRITE` | Output | 1 each | Its operation |
| `WRITE_DATA`, `WRITE_MASK` | Output | W, W/8 | Its data and mask |
| `READ_STROBE`, `WRITE_STROBE` | Output | 1 each | The one edge at which the access happens, only when its status is OK |
| `BACK_STATUS`, `BACK_READ_DATA` | Input | 3, W | The device's answer for the held request |
| `BACK_READY` | Input | 1 | Low delays a write (the device has no room) |

### Behavior

The port takes a request, checks the parts every register access shares
(alignment to W/8, a known operation, a full or empty mask), and asks the
device for its answer. At the execute edge it raises `READ_STROBE` or
`WRITE_STROBE` once, samples `BACK_STATUS` and `BACK_READ_DATA`, and holds
the answer until the bus takes it. Cycle by cycle: the accepting edge
captures the request and lowers `REQ_READY`; in the next cycle the strobe is
high and the answer is already on `RSP_*`, because the empty response buffer
passes it straight through; the execute edge ends the strobe, and the buffer
keeps the sampled answer until `RSP_READY` takes it. A read never has a side effect, so
reading a queue's head twice gives the same event; side effects happen only
through writes. A zero write mask does nothing; a partial mask is Invalid.

The shared validation priority is unknown operation/address → Invalid (6),
unsupported operation → Unsupported (4), invalid write mask → Invalid (6),
then misalignment → Alignment (1). Only if these pass does `BACK_STATUS`
decide the result. A valid nonzero-mask write waits for `BACK_READY`; reads,
errors and zero-mask writes do not. A zero-mask write can still report a
register access error: side-effect-free does not mean every address is OK.

Reset drops a pending access and held answer. It suppresses admission and
execution while asserted; it cannot undo a strobe the device already acted
on. The response buffer samples a read once, so later changes in a counter
or queue do not change a backpressured response. Strobes are qualified
enables around the execute edge, not extra clocks.

### Implementation

`REQUEST` validates and captures operation, offset, payload, mask and the
shared status. `CONTROL` tracks pending/executed state and backend readiness.
`EXECUTE` selects the final status, gates strobes and returns zero for a
write or failed read. `RESPONSE` is the structural memory response buffer
that holds sampled data/status until consumption. At W = 32 the compact
port compiles these same gates with characterized storage.

**Timing.** Request fields must meet the capture edge; backend data/status
must settle for execution. The buffer retains the sampled answer independently
of later backend changes. Selected default 32-bit paths, with reset low:

## 5.4.1.2. The register front end

### IO pins

| Pin | Direction | Width | Meaning |
| --- | --- | ---: | --- |
| `ADDRESS`, `IS_WRITE`, `WRITE_DATA`, `WRITE_MASK`, `WRITE_STROBE` | Input | 32, 1, 32, 4, 1 | From the register port |
| `READY` | Input | 1 | The device's write readiness, passed to `BACK_READY` |
| `<NAME>_VALUE` | Input | the register's bits | Per read-only register: its value from the core |
| `CLK`, `RST` | Input | 1 each | Only when the table has a read-write register |
| `BACK_STATUS`, `BACK_READY`, `BACK_READ_DATA` | Output | 3, 1, 32 | To the register port |
| `<NAME>_WRITE` | Output | 1 | Per writable register: the write strobe (a command's only with value 1) |
| `<NAME>` | Output | the register's bits | Per read-write register: its stored value |

### Implementation

Four groups, in the order an access flows through them:

| Part | Built from the table |
| --- | --- |
| `DECODE` | `OFFSET_DECODE`, one `Decoder<n>` on the word index (address bits 2 to n+1), enabled only when the byte bits and every higher bit are 0 — one decoder, not one 32-bit comparison per register. Its outputs are one `SELECT_<NAME>` line per register |
| `CHECKS` | Two groups. `PAYLOAD`: `DATA_KNOWN` and, per writable register, no unknown bits and nothing above its width; `BAD` when the selected register's value does not fit. `STATUS`: the status as three-bit 2:1 selections in the order above, each on word gates (`<CHOICE>_LOW` = low & ~select, `<CHOICE>_HIGH` = high & select, `<CHOICE>` = their OR, all `ANDGate<3>`/`ORGate<3>`; the same per-bit gates and depth as a scalar mux); gives `BACK_STATUS` |
| `WRITES` | Per writable register its strobe (`SELECT_<NAME>` AND `WRITE_STROBE`; a command also needs bit 0), and per read-write register its `<NAME>_STATE`, a `Register<bits>` written by that strobe |
| `READS` | A chain of `Mux<2,32>`, `READ_<NAME>` for each readable register, from zero; gives `BACK_READ_DATA` |

`BACK_READY` is `READY` passed straight through.

In a compact device the front end is compiled into a gate list with the
rest of the device's groups.

The front end is a private group, not an independently selectable catalog
family. Writable strobes rely on the register port's already-qualified
`WRITE_STROBE`: driving this group directly bypasses those shared checks.
The decoder checks the complete word offset, so an unmapped high address
does not alias a low register. Tables reject duplicate or unaligned offsets,
offsets at or above `0x80`, duplicate names and widths outside 1–32.
Command entries must have width 1. Current stored registers reset to zero;
nonzero read-write reset values are not implemented by this builder.

`REQ_OP`, `REQ_ADDR` and a write mask containing `X`/`Z` are rejected by the
port's known-bit checks. A selected writable payload with unknown bits is
Invalid when the mask is nonzero. Read-only values may themselves contain
unknown bits and are returned as data; they are not automatically an error.
These rules do not establish equivalence for unknown clocks or handshake
controls. The front end's compiled delay table is derived for its actual
register list and is not a separately stored whole-device table.

### Example: the console's table

| Offset | Register | Access | Bits | Meaning |
| --- | --- | --- | ---: | --- |
| `0x0` | `TX` | write-only data | 8 | Queue one byte for the host |
| `0x4` | `STATUS` | read-only | 1 | Bit 0 `ROOM`: the queue has room |
| `0x8` | `COUNT` | read-only | 3 | Bytes waiting |

The word index needs two bits (offsets 0, 4, 8), so `OFFSET_DECODE` is a
`Decoder<2>`. A read of `0x0` selects `TX`, a write-only register: status
Unsupported. A write of `0x141` to `TX` does not fit 8 bits: Invalid. A read
of `0xC`: decoder output 3 has no register, so Range.
