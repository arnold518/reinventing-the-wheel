# § 1.5. Selection and Decoding

A multiplexer picks one of several inputs by a select number; a decoder turns
a number into one active line. Both are built from the gates of
[§ 1.3](1.3.md), and both keep the gates' four-state behavior in their
compact forms.

| Component | Description | Structural | Behavioral |
| --- | --- | :---: | :---: |
| `Mux<N,W>` | Passes the selected one of N W-bit inputs | Yes | Yes |
| `Decoder<N>` | Raises the one of 2^N outputs that the N-bit address selects | Yes | Yes |

## 1.5.1. `Mux<N,W>`

`Mux<N,W>` passes one of its N inputs, each W bits wide, to its output. N is
2, 4, 8, 16 or 32 and W is 1, 4, 8, 16 or 32; each geometry is its own
contract `logic.mux.<N>.<W>`, returned by `circuit::word::mux(N, W)`. The
recorded example is `Mux<2,1>`.

### IO pins

| Pin | Direction | Width | Description |
| --- | --- | ---: | --- |
| `A`, `B` | Input | W each | The two inputs (N = 2) |
| `IN0` … `IN<N−1>` | Input | W each | The inputs (N > 2) |
| `SEL` | Input | log₂(N) | Which input to pass |
| `OUT` | Output | W | The selected input |

### Behavior

With a binary `SEL` of value k, `OUT` equals input k (`A` for 0 and `B` for 1
when N = 2). Each output bit is chosen independently, by a tree of two-input
muxes: level 0 pairs neighbouring inputs by `SEL` bit 0, level 1 pairs those
results by `SEL` bit 1, and so on.

#### C++ example

```cpp
#include <cstdint>
#include <vector>

uint64_t mux_ref(const std::vector<uint64_t>& inputs, unsigned select) {
    return inputs.at(select);
}
```

This binary function describes the settled output. It is not a registered implementation.

#### Unknown inputs

A two-input mux is built as `(A AND NOT SEL) OR (B AND SEL)`, not as an
optimistic conditional: with `SEL` unknown, the output is 0 when both data
bits are 0, and `X` otherwise (even when both are 1, because each AND term
alone is unknown). With `SEL` known, the unselected input does not matter;
the selected one passes through the gates, so a `Z` there gives `X`. A tree
applies this rule at every level.

### Implementation

#### Structural implementation

- `Mux<2,1>`: `NOT_SEL` (NOT), `AND_A` (`A` AND NOT `SEL`), `AND_B` (`B` AND
  `SEL`) and `OR_OUT`.
- `Mux<N,1>` for N > 2: `SEL_SPLIT` and a balanced tree of `Mux<2,1>` named
  `MUX_L<level>_<index>`, level ℓ selecting by `SEL` bit ℓ.
- `Mux<2,W>` for W > 1: `A_SPLIT`, `B_SPLIT`, one shared `NOT_SEL`, and for
  each bit `SELECT_A_<i>`, `SELECT_B_<i>` and `COMBINE_<i>` (the same AND/AND/OR
  as `Mux<2,1>`), joined by `OUT_JOIN`.
- `Mux<N,W>` for N > 2 and W > 1: a splitter per input, one `Mux<N,1>` per
  bit (`MUX_BIT_<i>`) sharing `SEL`, and `OUT_JOIN`.

#### Behavioral implementation

One leaf evaluates, for every output bit, the same tree of two-input muxes
with the gate rule above, and publishes the word on the delays proven on the
gates ([§ 1.2 Compact parts](1.2.md#compact-parts)). Every geometry has it.

## 1.5.2. `Decoder<N>`

`Decoder<N>` raises the one output line whose number is the N-bit address,
while `ENABLE` is high. N is 1 to 5. The contract is `logic.decoder.<N>.full`;
the variant `logic.decoder.<N>.zero-disabled` ties output 0 low and builds no
logic for it (the register file uses it, because register x0 has no storage).
The recorded example is `Decoder<5>`.

### IO pins

| Pin | Direction | Width | Description |
| --- | --- | ---: | --- |
| `ADDR` | Input | N | The output number |
| `ENABLE` | Input | 1 | Low forces every output low |
| `OUT0` … `OUT<2^N−1>` | Output | 1 each | `OUTk` is high when `ENABLE` is high and `ADDR` = k |

### Behavior

With binary inputs exactly one output is high when `ENABLE` is high, and none
when it is low. In the zero-disabled variant `OUT0` is always low.

#### C++ example

```cpp
#include <cstdint>
#include <vector>

std::vector<bool> decoder_ref(unsigned address, bool enable, unsigned bits) {
    std::vector<bool> out(1u << bits, false);
    if (enable) out.at(address) = true;
    return out;
}
```

This binary function describes the settled outputs. It is not a registered implementation.

#### Unknown inputs

Each output is an AND of `ENABLE` and one literal (the bit or its inverse) per
address bit. A low `ENABLE` makes every output 0. An unknown or floating
address bit makes `X` every output whose other literals are all 1 and 0 every
output that another literal already rules out.

### Implementation

#### Structural implementation

At N = 5: `ADDR_SPLIT`, one word inverter `NOT_ADDR` (`NOTGate<5>`) with its
bits split by `NOT_ADDR_BITS`, predecoding gates `LOW_0` … `LOW_3` (address
bits 0–1), `HIGH_PAIR_0` … `HIGH_PAIR_7` (bits 2–3) and `HIGH_0` … `HIGH_7`
(with bit 4), and one `MATCH_<k>` AND per output joining a low and a high
term. The 32 matches are joined into `MATCH_WORD`, ANDed with `ENABLE` spread
across the word (`ENABLE_WORD`) in one word gate `ENABLE` (`ANDGate<32>`, or
`ANDGate<31>` in the zero-disabled variant), and split to the outputs by
`OUT_BITS`. At N = 1 to 4 each output is a balanced AND tree of `ENABLE` and
its N literals, after one inverter per address bit.

#### Behavioral implementation

At N = 5 one leaf evaluates the same literals and AND terms with the gate
rule, so unknown address bits give the gates' outputs, on the delays proven
on the gates. At N = 1 to 4 the compact form evaluates the decoder's own gate
list ([§ 1.1](1.1.md#structural-and-compact-forms)); it is chosen only
explicitly, for example by collapsing the part in the simulator.
