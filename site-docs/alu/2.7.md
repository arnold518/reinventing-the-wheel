# § 2.7. Integer Datapath

`Operations::IntegerDatapath` defines a 13-operation ALU contract at W = **8, 16 or 32**. The operation map, control pins and flag qualification are independent of operand width. `ALUConfig.adder` chooses ripple or parallel-prefix hardware; `full_flags` chooses the complete or result/comparison-only interface.

| Component | Description | Structural | Behavioral |
| --- | --- | :---: | :---: |
| `AddSub<W>` | Addition/subtraction with SUB supplying carry-in | Yes | Yes |
| `LogicUnit<W>` | Three simultaneous bitwise results | Yes | Yes |
| `BarrelShifter<W>` | Logical left/right and arithmetic right shifts | Yes | Yes |
| `ALUControlDecoder` | Integer operation decoding, independent of W | Yes | No |
| `CompareSelect<W>` | Qualified comparison flags and Boolean words | Yes | No |
| `ALUResultSelector<W>` | Integer result selection | Yes | No |
| `ALUFlagUnit<W>` | Result flags and arithmetic qualification | Yes | No |
| `ALU<W>` | Complete integer datapath operation contract | Yes | Yes |

The behavioral column describes the recorded **32-bit prefix** configuration. Other widths/topologies use structural circuits unless their catalog family supplies a matching behavioral factory. The binary C++ references take W as a template parameter; recorded examples instantiate W = 32 and the IO tables use W. The reference inputs must fit their documented pin widths; binary arithmetic wraps modulo 2^W.

These interfaces differ from the [extended operation contract](2.6.md): there is no carry input, rotation or invalid-operation output; comparisons retain subtraction flags. The 32-bit prefix configurations expose either full result flags or the reduced
core interface. [RV32I ALU integration](../rv32i/4.3/alu.md) specifies the CPU configuration and its use in Execute.

## 2.7.1. `AddSub<W>`

### IO pins

| Pin | Direction | Width | Description |
| --- | --- | ---: | --- |
| `A`, `B` | Input | W each | Operands |
| `SUB` | Input | 1 | 0: addition; 1: subtraction |
| `OUT` | Output | W | Wrapped result |
| `CARRY_OUT` | Output | 1 | Addition carry; subtraction **no borrow** |
| `OVERFLOW` | Output | 1 | Signed overflow |

### Behavior

The shared adder computes `A + (B XOR {W{SUB}}) + SUB`. Subtraction therefore sets carry when unsigned `A >= B`. Overflow is independent of unsigned carry.

#### C++ example

```cpp
#include <array>
#include <cstdint>
namespace integer_alu_example {
template<unsigned W> struct Domain {
    static_assert(W == 8 || W == 16 || W == 32);
    static constexpr uint64_t mask = (uint64_t{1} << W) - 1;
    static constexpr uint64_t sign = uint64_t{1} << (W - 1);
};
struct Arithmetic { uint32_t OUT; bool CARRY_OUT, OVERFLOW; };
template<unsigned W>
Arithmetic addsub(uint32_t a, uint32_t b, bool sub) {
    const uint64_t wide = uint64_t(a) + (sub ? (uint64_t(b) ^ Domain<W>::mask) : b) + sub;
    const uint32_t out = uint32_t(wide & Domain<W>::mask);
    const bool overflow = ((sub ? (a ^ b) : ~(a ^ b)) & (a ^ out) & Domain<W>::sign) != 0;
    return {out, bool(wide >> W), overflow};
}
}
```

#### Unknown inputs

Each bit follows XOR/AND/OR full-adder logic. A known controlling zero or one can mask an unknown; the entire word is not automatically discarded. Carry propagation follows the selected ripple or prefix network. The catalog-selected behavioral implementation uses gate-derived path delays; a supported delay twin can time how far the carry propagates for the current operands.

### Implementation

#### Structural implementation

Each B bit passes through an XOR with `SUB`; `SUB` also supplies carry-in to the shared prefix adder. A joiner collects sums. XOR of the carry into and out of bit W−1 produces overflow. The optional ripple reference instead uses W chained `FullAdder` stages.

With `ParallelPrefix` topology, `ParallelPrefixAdder<W>` builds half-adder propagate/generate cells and log₂(W) carry-combination levels. `CarryCombine` contains AND/OR gates. Overflow is carry into the sign bit XOR carry out. The ripple topology uses W chained `FullAdder` cells and the same external contract.

`AddSub<32,integer,prefix>` is the 32-bit prefix family. The generic constructor selects `Operations::IntegerDatapath` explicitly; its topology is supplied independently. `ArithmeticTimingOptimizationTest` covers width and topology, including their actual prefix-level structure.

#### Behavioral implementation

The compact factory belongs to the 32-bit family; other widths/topologies are structural. 
`AddSub<32,integer,prefix>Behavioral` evaluates that same full-adder recurrence with four-state bit values, without constructing its internal gates.

**Timing.** The carry crosses 32 bits in five prefix levels instead of 32 ripple stages,
so the depth grows with log₂ of the width rather than with the width. In the
realistic profiles the 32-bit unit settles sooner than the 8-bit
[ripple unit](2.1.md#214-addsubw) of the extended operation contract, a quarter of its
width; in `unit`, where every gate costs one tick, the two are about equal.

## 2.7.2. `LogicUnit<W>`

### IO pins

| Pin | Direction | Width | Description |
| --- | --- | ---: | --- |
| `A`, `B` | Input | W each | Operands |
| `AND_OUT`, `OR_OUT`, `XOR_OUT` | Output | W each | Three simultaneous bitwise results |

### Behavior

All three outputs are active together; there is no opcode or enable.

#### C++ example

```cpp
namespace integer_alu_example {
struct Logic { uint32_t AND_OUT, OR_OUT, XOR_OUT; };
template<unsigned W>
Logic logic(uint32_t a, uint32_t b) { return {a & b, a | b, a ^ b}; }
}
```

#### Unknown inputs

AND with zero produces zero; OR with one produces one. Other indeterminate cases produce `X`, including XOR with `X` or `Z`. Operations are independent per bit.

### Implementation

#### Structural implementation

Two splitters, W gates of each operation, and three joiners provide three parallel paths.

#### Behavioral implementation

The compact factory belongs to the 32-bit family; other widths/topologies are structural. 
`LogicUnit<32,integer>Behavioral` applies the same four-state gate rules per bit and publishes when the gate-level form would have settled for the same inputs.

## 2.7.3. `BarrelShifter<W>`

### IO pins

| Pin | Direction | Width | Description |
| --- | --- | ---: | --- |
| `A` | Input | W | Word being shifted |
| `B` | Input | W | Shift amount is **only** the low log₂(W) bits of B |
| `LEFT` | Input | 1 | 1: left; 0: right |
| `ARITHMETIC` | Input | 1 | Sign-fill for right shifts; ignored for left shifts |
| `OUT` | Output | W | Shifted word |

### Behavior

Shift distance is 0–W−1. Left shifts and logical right shifts fill with zero; arithmetic right shifts fill with the original sign bit. A distance of zero preserves the word. There is no shifted-out carry output.

#### C++ example

```cpp
namespace integer_alu_example {
template<unsigned W>
uint32_t shift(uint32_t a, uint32_t b, bool left, bool arithmetic) {
    const unsigned n = b & (W - 1);
    if (left) return uint32_t((uint64_t(a) << n) & Domain<W>::mask);
    uint32_t out = a >> n;
    if (n && arithmetic && (a & Domain<W>::sign)) out |= uint32_t(Domain<W>::mask << (W - n));
    return out & Domain<W>::mask;
}
}
```

#### Unknown inputs

B bits above the low log₂(W) distance bits are unused, even when unknown. The remaining bits follow the gate-based mux network; an unknown selector does not necessarily preserve equal one-valued mux inputs. Left shifting disables sign fill. The structural path includes log₂(W) selectable shift stages.

### Implementation

#### Structural implementation

A shared right-shift network selects distances 1, 2, 4, …, W/2. Input/output reversal muxes reuse it for left shifts. Fill is `A[31] AND ARITHMETIC AND NOT LEFT`.

#### Behavioral implementation

The compact factory belongs to the 32-bit family; other widths/topologies are structural. 
`BarrelShifter<32,integer>Behavioral` reproduces the reversal, each mux stage, and fill logic using four-state values. Catalog construction gives it gate-derived output delays, with a delay twin where supported to time the current shift and data.

## 2.7.4. `ALUControlDecoder`

### IO pins

| Pin | Direction | Width | Description |
| --- | --- | ---: | --- |
| `OP` | Input | 5 | Complete opcode |
| `LOCAL_OP` | Output | 3 | `OP[2:0]` |
| `HIGH_HALF`, `OUT_OF_RANGE` | Output | 1 each | `OP[3]`, `OP[4]` |
| `ARITHMETIC_ENABLE` | Output | 1 | Qualifies carry and overflow |
| `SUB` | Output | 1 | Requests subtraction and enables comparisons |
| `SHIFT_LEFT`, `SHIFT_ARITHMETIC` | Output | 1 each | Shifter controls |

### Behavior

Arithmetic flags are enabled for 0, 1, 8, 9; subtraction for 1, 8, 9. Shift controls are raw Boolean functions, **not** shift-operation enable flags. They can be high when another result source is selected. `OUT_OF_RANGE` only detects 16–31; selectors also map reserved 13–15 to zero.

#### C++ example

```cpp
namespace integer_alu_example {
struct Control {
    unsigned LOCAL_OP;
    bool HIGH_HALF, OUT_OF_RANGE, ARITHMETIC_ENABLE, SUB, SHIFT_LEFT, SHIFT_ARITHMETIC;
};
Control control(unsigned op) { // OP is a five-bit input.
    const bool arithmetic = !(op & 16) && !(op & 4) && !(op & 2);
    return {op & 7, bool(op & 8), bool(op & 16), arithmetic,
            arithmetic && bool(op & 9), !(op & 2), bool(op & 1)};
}
}
```

#### Unknown inputs

Rewired selector bits preserve `X`/`Z`; logic-derived controls follow their gates. Outputs are combinational and need time to settle.

### Implementation

#### Structural implementation

A splitter and selector joiner expose opcode bits; NOT/AND/OR gates derive the enables. No behavioral implementation is registered for this helper.

## 2.7.5. `CompareSelect<W>`

### IO pins

| Pin | Direction | Width | Description |
| --- | --- | ---: | --- |
| `DIFF` | Input | W | `A - B` from the shared subtractor |
| `CARRY_IN`, `OVERFLOW_IN` | Input | 1 each | Subtraction no-borrow and signed overflow |
| `ENABLE` | Input | 1 | Enable comparisons |
| `EQ`, `LT_SIGNED`, `LT_UNSIGNED` | Output | 1 each | Comparison flags |
| `SLT_RESULT`, `SLTU_RESULT` | Output | W each | Corresponding less-than flag in bit 0; bits W−1:1 zero |

### Behavior

This helper consumes an existing subtraction; it is not an independent two-operand comparator. Signed comparison corrects the difference sign using overflow. All comparisons are zero when disabled. The W-bit outputs are ALU result words, not W-bit flags.

#### C++ example

```cpp
namespace integer_alu_example {
struct Compare { bool EQ, LT_SIGNED, LT_UNSIGNED; uint32_t SLT_RESULT, SLTU_RESULT; };
template<unsigned W>
Compare compare(uint32_t diff, bool carry, bool overflow, bool enable) {
    const bool s = enable && (bool(diff & Domain<W>::sign) != overflow);
    const bool u = enable && !carry;
    return {enable && diff == 0, s, u, uint32_t(s), uint32_t(u)};
}
}
```

#### Unknown inputs

Disabled AND outputs mask unknown arithmetic inputs. Enabled flags use four-state zero-detection, XOR, and inversion. Upper Boolean-result bits remain constant zero.

### Implementation

#### Structural implementation

`ZeroDetect<W>` forms equality; a sign splitter, XOR, NOT, and AND gates form less-than flags. Joiners extend those flags to words. No behavioral implementation is registered for this helper.

## 2.7.6. `ALUResultSelector<W>`

### IO pins

| Pin | Direction | Width | Description |
| --- | --- | ---: | --- |
| `ARITHMETIC_RESULT`, `AND_RESULT`, `OR_RESULT`, `XOR_RESULT`, `SHIFT_RESULT` | Input | W each | Operation-unit results |
| `SLT_RESULT`, `SLTU_RESULT`, `A`, `B` | Input | W each | Comparison results and pass-through operands |
| `LOCAL_OP` | Input | 3 | Index within a group |
| `HIGH_HALF` | Input | 1 | Choose high group |
| `OUT_OF_RANGE` | Input | 1 | Force zero |
| `OUT` | Output | W | Selected word |

### Behavior

Low-group sources are arithmetic, arithmetic, AND, OR, XOR, shift, shift, shift. High-group sources are SLT, SLTU, A, B, zero, zero, zero, zero. `OUT_OF_RANGE` overrides both groups with zero. Inputs are independently meaningful even when no decoder is attached.

#### C++ example

```cpp
namespace integer_alu_example {
template<unsigned W>
uint32_t select(uint32_t arithmetic, uint32_t and_result, uint32_t or_result,
                uint32_t xor_result, uint32_t shifted, uint32_t slt, uint32_t sltu,
                uint32_t a, uint32_t b, unsigned local, bool high, bool invalid) {
    const std::array<uint32_t,8> low{arithmetic,arithmetic,and_result,or_result,xor_result,shifted,shifted,shifted};
    const std::array<uint32_t,8> upper{slt,sltu,a,b,0,0,0,0};
    return invalid ? 0 : (high ? upper : low).at(local);
}
}
```

#### Unknown inputs

Known controls mask unselected paths; unknown controls follow the mux gate equations. The decoded AND/OR network preserves those equations, including repeated arithmetic/shift choices with unknown selector bits. Outputs settle after gate propagation.

### Implementation

#### Structural implementation

Parallel opcode minterms qualify nine result sources. `BIT_0` through `BIT_(W−1)` are expandable `ALUResultBit` slices: each masks the nine source bits and combines them with a balanced OR tree. Invalid operations select no source and produce zero. Selection has no serial mux chain or stored state. No behavioral implementation is registered for this helper.

`RV32ILogicOptimizationTest` compares this circuit with the gate-built mux reference across all 1,024 four-state selector combinations, each with four data patterns (4,096 rows).

## 2.7.7. `ALUFlagUnit<W>`

### IO pins

| Pin | Direction | Width | Description |
| --- | --- | ---: | --- |
| `RESULT` | Input | W | Selected final result |
| `ARITHMETIC_ENABLE` | Input | 1 | Enables arithmetic flags |
| `ARITH_CARRY`, `ARITH_OVERFLOW` | Input | 1 each | Shared adder flags |
| `ZERO`, `NEGATIVE`, `CARRY_OUT`, `OVERFLOW` | Output | 1 each | Result and qualified arithmetic flags |

### Behavior

Zero and negative always describe the final result. Carry and overflow are passed only when enabled. Comparison flags do not belong to this block.

#### C++ example

```cpp
namespace integer_alu_example {
struct Flags { bool ZERO, NEGATIVE, CARRY_OUT, OVERFLOW; };
template<unsigned W>
Flags flags(uint32_t result, bool enable, bool carry, bool overflow) {
    return {result == 0, bool(result & Domain<W>::sign), enable && carry, enable && overflow};
}
}
```

#### Unknown inputs

Negative directly exposes result bit W−1, including `Z`; zero uses a gate reduction. Disabled carry/overflow are zero even if their arithmetic inputs are unknown.

### Implementation

#### Structural implementation

`ZeroDetect<W>`, a `SIGN_BIT` rewire and two AND gates implement this block. SIGN_BIT maps RESULT[W−1] directly to NEGATIVE without a logic gate, preserving X/Z. Its input has W bits and its output has one bit; there are no unused sign-split outputs. The integer flag helper has no standalone behavioral factory.

## 2.7.8. `ALU<W>`

### IO pins

This table describes `full_flags=true`. With `full_flags=false`, ZERO,
NEGATIVE, CARRY_OUT and OVERFLOW are absent; OUT and the three comparison
outputs remain. This choice applies at every supported W.

| Pin | Direction | Width | Description |
| --- | --- | ---: | --- |
| `A`, `B` | Input | W each | Operands |
| `OP` | Input | 5 | Integer operation |
| `OUT` | Output | W | Result |
| `ZERO`, `NEGATIVE` | Output | 1 each | Result zero/sign |
| `CARRY_OUT`, `OVERFLOW` | Output | 1 each | Qualified arithmetic flags |
| `EQ`, `LT_SIGNED`, `LT_UNSIGNED` | Output | 1 each | Qualified subtraction comparisons |

### Behavior

| OP | Operation | OUT | Carry/overflow | Comparison flags |
| ---: | --- | --- | --- | --- |
| 0 | ADD | `A + B` | Addition | Zero |
| 1 | SUB | `A - B` | Subtraction | Valid |
| 2 | AND | `A & B` | Zero | Zero |
| 3 | OR | `A \| B` | Zero | Zero |
| 4 | XOR | `A ^ B` | Zero | Zero |
| 5 | SLL | `A << (B & (W−1))` | Zero | Zero |
| 6 | SRL | Logical `A >> (B & (W−1))` | Zero | Zero |
| 7 | SRA | Arithmetic `A >> (B & (W−1))` | Zero | Zero |
| 8 | SLT | Signed `A < B`, extended to W bits | Subtraction | Valid |
| 9 | SLTU | Unsigned `A < B`, extended to W bits | Subtraction | Valid |
| 10 | PASS_A | A | Zero | Zero |
| 11 | PASS_B | B | Zero | Zero |
| 12 | ZERO | 0 | Zero | Zero |
| 13–31 | Reserved | 0 | Zero | Zero |

For every opcode, `ZERO = (OUT == 0)` and `NEGATIVE = OUT[W−1]`. SLT/SLTU retain subtraction carry/overflow even though their final result is only zero or one. `EQ` is not an always-on operand-equality indicator. Branch instructions select `SUB` to obtain all three comparisons. Reserved operations produce `ZERO=1`, all other flags zero; instruction legality is the decoder's responsibility.

#### C++ example

```cpp
namespace integer_alu_example {
struct Result {
    uint32_t OUT;
    bool ZERO, EQ, LT_SIGNED, LT_UNSIGNED, NEGATIVE, CARRY_OUT, OVERFLOW;
};
template<unsigned W>
Result alu(uint32_t a, uint32_t b, unsigned op) {
    const auto c = control(op);
    const auto ar = addsub<W>(a,b,c.SUB);
    const auto l = logic<W>(a,b);
    const auto sh = shift<W>(a,b,c.SHIFT_LEFT,c.SHIFT_ARITHMETIC);
    const auto cmp = compare<W>(ar.OUT,ar.CARRY_OUT,ar.OVERFLOW,c.SUB);
    const auto out = select<W>(ar.OUT,l.AND_OUT,l.OR_OUT,l.XOR_OUT,sh,
        cmp.SLT_RESULT,cmp.SLTU_RESULT,a,b,c.LOCAL_OP,c.HIGH_HALF,c.OUT_OF_RANGE);
    const auto f = flags<W>(out,c.ARITHMETIC_ENABLE,ar.CARRY_OUT,ar.OVERFLOW);
    return {out,f.ZERO,cmp.EQ,cmp.LT_SIGNED,cmp.LT_UNSIGNED,f.NEGATIVE,f.CARRY_OUT,f.OVERFLOW};
}
}
```

#### Unknown inputs

Structural gates can mask unused/unknown inputs. For the 32-bit configuration, `WordBehavioral<W, Topology>` makes **all outputs unknown if any bit of A, B, or OP is nonbinary**, including an unused operand. Its equivalence claim is settled **binary** behavior, not full four-state or transient equivalence. There is no clock: wait for propagation before sampling.

### Implementation

#### Structural implementation

The root contains `CONTROL`, `ARITHMETIC`, `LOGIC`, `SHIFT`, `COMPARE` and
`RESULT_SELECT`. Full-flag configurations also contain `FLAGS`. Arithmetic
results feed comparison; control selects a result and qualifies flags. Each
group can be expanded independently in the visualizer.

#### Behavioral implementation


`WordBehavioral<W, Topology>` computes the selected operation and flags directly. When its delay twin agrees with that result, the catalog-selected part can use the current operands' gate-list settling time within its per-operation delay-table bound; an older pending result still retains publication order. If the twin cannot answer, the table supplies the timing. The registered contract is `word.alu.32.integer.prefix`; structural remains available. Inside a structural integer ALU, arithmetic, logic, shift and zero-detect children are required to be structural. Their standalone catalog families declare their own fidelities.

**Timing.** The following paths describe the complete 32-bit prefix family. The core configuration omits the final result flags, so its critical paths differ. Width, topology, flag interface and timing profile each belong to the characterized contract.
