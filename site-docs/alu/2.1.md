# § 2.1. Arithmetic Components

`Adder<W>`, `AddSub<W>` and `ArithmeticUnit<W>` build word arithmetic from one-bit gates and cells. Width, addition topology and arithmetic control are separate choices. `Adder<W>` selects ripple or parallel-prefix addition. This page's add/subtract and operation-selection interfaces use `Operations::Extended`; the [integer datapath contract](2.7.md) ties subtraction carry-in to `SUB`.

Bits are numbered from 0 at the least significant position. Let $M=2^W$ and $S=2^{W-1}$. Results wrap modulo M; signed values range from $-S$ to $S-1$. Carry is unsigned carry/no-borrow and is independent of signed overflow. These are combinational components with no clock or stored flags.

| Component | Description | Structural | Behavioral |
| --- | --- | :---: | :---: |
| `HalfAdder` | One-bit sum and carry, without carry-in | Yes | No |
| `FullAdder` | One-bit addition with carry-in | Yes | No |
| `Adder<W>` | Word adder with ripple or parallel-prefix carry | Yes | Yes |
| `AddSub<W>` | Conditional B inversion, independent carry input and signed overflow | Yes | Yes |
| `ArithmeticUnit<W>` | Seven arithmetic operations over one shared add/subtract path | Yes | Yes |
| `ParallelPrefixAdder<W>` | Optimized carry network used inside the ALU | Yes | No |

W is **8, 16 or 32**. The behavioral column describes the recorded eight-bit ripple configuration; other word widths/topologies use structural circuits unless their catalog family provides a matching behavioral factory. The binary C++ references use W as a parameter. Recorded tables identify their concrete width; the prefix recording uses W = 16. [Configuration and family selection](../components/word-components.md) specifies construction.

## 2.1.1. `HalfAdder`

`HalfAdder` adds two one-bit operands. It has no carry input, so it cannot by itself be a general cell in a multi-bit carry chain.

### IO pins

| Pin | Direction | Width | Description |
| --- | --- | ---: | --- |
| `A` | Input | 1 | First operand bit |
| `B` | Input | 1 | Second operand bit |
| `Sum` | Output | 1 | Low bit of the sum |
| `Carry` | Output | 1 | Carry into the next bit position |

The output is named `Carry`, not `Carry_out` or `Cout`. Pin names are case-sensitive.

### Behavior

For binary inputs,

$$
\begin{aligned}
\mathrm{Sum} &= A \oplus B, \\
\mathrm{Carry} &= A \land B.
\end{aligned}
$$

Interpreting the bits as unsigned integers, `A + B = Sum + 2*Carry`. For example, `1 + 1` gives `Sum = 0`, `Carry = 1`. The component has no clock, stored state, or flags beyond this carry.

#### C++ example

```cpp
struct HalfAdderResult {
    bool Sum;
    bool Carry;
};

HalfAdderResult half_adder_ref(bool a, bool b) {
    return {a != b, a && b};
}
```

This binary-only function describes the settled outputs. It is not a registered behavioral implementation.

#### Unknown inputs

The simulator's XOR produces `X` if either input is `X` or `Z`. The AND produces 0 if either input is definitely 0, 1 only if both are definitely 1, and `X` otherwise. Neither output drives `Z`.

| `A` | `B` | Settled `Sum` | Settled `Carry` |
| --- | --- | --- | --- |
| 0 | `X` or `Z` | `X` | 0 |
| 1 | `X` or `Z` | `X` | `X` |

### Implementation

#### Structural implementation

Both inputs fan out to two gates, which operate in parallel:

| Child | Type | Inputs → output |
| --- | --- | --- |
| `XOR1` | `XORGate` | `A`, `B` → `Sum` |
| `AND1` | `ANDGate` | `A`, `B` → `Carry` |

There is no internal carry chain or storage. `HalfAdder` has only this structural implementation; the two gates remain visible in the simulator.

## 2.1.2. `FullAdder`

`FullAdder` adds two one-bit operands and a carry input. Its carry output can feed the next bit position; eight such cells form `Adder<8,ripple>`.

### IO pins

| Pin | Direction | Width | Description |
| --- | --- | ---: | --- |
| `A` | Input | 1 | First operand bit |
| `B` | Input | 1 | Second operand bit |
| `Carry_in` | Input | 1 | Carry from the previous bit position |
| `Sum` | Output | 1 | Low bit of the three-input sum |
| `Carry_out` | Output | 1 | Carry into the next bit position |

`Carry_in` and `Carry_out` are the actual pins; they are not named `Cin` and `Cout` as on `Adder<8,ripple>`.

### Behavior

Define the first half adder's sum as `P = A XOR B`. For binary inputs,

$$
\begin{aligned}
\mathrm{Sum} &= P \oplus \mathrm{Carry\_in}, \\
\mathrm{Carry\_out} &= (A \land B) \\
&\quad \lor (P \land \mathrm{Carry\_in}).
\end{aligned}
$$

Thus `A + B + Carry_in = Sum + 2*Carry_out`. With three input ones, the result is `Sum = 1`, `Carry_out = 1`; with exactly two ones, it is `Sum = 0`, `Carry_out = 1`. The carry is not a signed-overflow indication.

#### C++ example

```cpp
struct FullAdderResult {
    bool Sum;
    bool Carry_out;
};

FullAdderResult full_adder_ref(bool a, bool b, bool carry_in) {
    const auto first = half_adder_ref(a, b);
    const auto second = half_adder_ref(first.Sum, carry_in);
    return {second.Sum, first.Carry || second.Carry};
}
```

This example reuses `half_adder_ref` above and follows the actual two-half-adder composition. It describes binary settled values, not simulator events or a selectable behavioral implementation.

#### Unknown inputs

`X`/`Z` inputs propagate through the two half adders and final OR gate. Use the stated XOR/AND/OR network, not an arbitrary binary-equivalent rewrite, to determine four-state results. For example:

| `A` | `B` | `Carry_in` | Settled `Sum` | Settled `Carry_out` |
| --- | --- | --- | --- | --- |
| 0 | 0 | `Z` | `X` | 0 |
| 1 | 1 | `X` | `X` | 1 |
| 1 | `X` | 1 | `X` | `X` |

In the last row, both the first sum and both intermediate carries are unknown. The binary-equivalent majority expression `(A AND B) OR (A AND Carry_in) OR (B AND Carry_in)` would instead yield carry 1 because `A AND Carry_in = 1`. That is **not** this structural circuit's four-state contract. Neither output drives `Z`.

### Implementation

#### Structural implementation

| Child | Type | Inputs → output |
| --- | --- | --- |
| `HA1` | `HalfAdder` | External `A`, `B` → intermediate sum and first carry |
| `HA2` | `HalfAdder` | `HA1.Sum`, external `Carry_in` → external `Sum` and second carry |
| `OR1` | `ORGate` | `HA1.Carry`, `HA2.Carry` → external `Carry_out` |

Expanding the two half adders reveals five primitive gates in total: two XORs, two ANDs, and one OR. There is no stored carry or clock. `FullAdder` has only this structural implementation.

In the eight-bit chain, `Adder<8,ripple>.Cin` drives `FA0.Carry_in`, each cell's `Carry_out` drives the next cell's `Carry_in`, and `FA7.Carry_out` drives `Adder<8,ripple>.Cout`. This is a ripple-carry connection, not eight independent additions.

**Timing.** The carry's longest path is `HA1.XOR1 → HA2.AND1 → OR1` (an XOR, an AND and an OR); the sum's is two XOR gates. Which is longer depends on the profile: in `unit` every gate is one tick, so the carry path is longer; in the realistic profiles an XOR costs about four inverter delays, so the sum path is.

## 2.1.3. `Adder<W>`

### IO pins

| Pin | Direction | Width | Description |
| --- | --- | ---: | --- |
| `A`, `B` | Input | W each | Unsigned operand patterns |
| `Cin` | Input | 1 | Initial carry |
| `Sum` | Output | W | Low W bits of the sum |
| `Cout` | Output | 1 | Carry beyond bit W−1 |

### Behavior

For $T=A+B+\mathrm{Cin}$, `Sum = T mod M` and `Cout = [T >= M]`. There are no signed-overflow, zero or negative outputs. Pin names are case-sensitive: `Cin`, `Sum` and `Cout` apply at every width.

#### C++ example

This binary reference is parameterized by W = 8, 16 or 32. Inputs must fit their documented pin widths. It omits propagation delays and X/Z values.

```cpp
#include <cstdint>

// Binary word domain used by the references in this chapter.
template<unsigned W>
struct WordReference {
    static_assert(W == 8 || W == 16 || W == 32);
    static constexpr std::uint64_t mask = (std::uint64_t{1} << W) - 1;
    static constexpr std::uint64_t sign = std::uint64_t{1} << (W - 1);
};

template<unsigned W>
struct AdderResult {
    std::uint32_t Sum;
    bool Cout;
};

template<unsigned W>
AdderResult<W> adder_ref(std::uint32_t a, std::uint32_t b, bool cin) {
    const std::uint64_t total = std::uint64_t(a) + b + cin;
    return {
        static_cast<std::uint32_t>(total & WordReference<W>::mask),
        total >= (WordReference<W>::mask + 1),
    };
}
```

#### Unknown inputs

Each bit follows XOR/AND/OR carry equations. Unknown bits can be masked by controlling inputs; they do not automatically invalidate the whole result. A Z entering a logic gate is treated as unknown. Ripple and prefix structures have their own four-state propagation and settling paths.

### Implementation

#### Structural implementation

The ripple-carry adder passes carry from one bit to the next. This is a combinational chain: “sequential carry” describes propagation order, and there is no clock or multi-cycle protocol. It contains two `BitSplitter<W>` components, W chained `FullAdder` cells and a `BitJoiner<W>`. `Cin` feeds FA0; the last cell supplies `Cout`.

The prefix topology contains `ParallelPrefixAdder<W>`. Half-adder cells produce bit propagate/generate signals; carry-combination levels at distances 1, 2, 4, … combine them in log₂(W) levels. Carry-in application and XOR gates form the sums. The prefix component also exposes carry into the sign bit as `C7`, `C15` or `C31`.

`Adder<W>` defaults to parallel-prefix carry at every width. Select
`AdderTopology::Ripple` explicitly to build the carry chain described here.
Both topologies use the same width-aware family and construction path.

#### Behavioral implementation

The settled-value rules are parameterized by W and addition topology in `ExtendedALUValueModel<W, Topology>` (`WordALUValueModel.hpp`). They use the same four-state gates, masks, carry construction and movement stages as the structural circuit. Word loops use W, the sign is bit W−1, and the shifter has log₂(W) stages. Operation codes and local selector sizes are control widths and remain independent of W.

A catalog behavioral factory is available only for its verified configuration. The eight-bit ripple adapter uses these shared rules with its characterized delay table; other configurations on this page remain structural. The value model alone does not supply timing or enable compact fidelity. `ALUWidthContractTest` compares both topologies at 8/16/32 bits against the gates and an independent binary reference; `ExtendedALUFidelityContractTest` retains the compact-fidelity checks for those configurations.

**Timing.** Ripple carry depth grows with W; prefix carry depth grows with log₂(W). Timing belongs to the chosen width, topology and profile. These paths describe the eight-bit ripple recording:

<!-- timing-rows

Slowest carry | word.adder.8.ripple.behavioral | A → Cout
Carry chain alone | word.adder.8.ripple.behavioral | Cin → Cout
-->

## 2.1.4. `AddSub<W>`

### IO pins

| Pin | Direction | Width | Description |
| --- | --- | ---: | --- |
| `A`, `B` | Input | W each | Operand patterns |
| `SUB` | Input | 1 | Invert every B bit when high |
| `C_IN` | Input | 1 | Independent initial carry |
| `OUT` | Output | W | Wrapped result |
| `CARRY_OUT` | Output | 1 | Addition carry or subtraction no-borrow |
| `OVERFLOW` | Output | 1 | Signed result outside −S…S−1 |

### Behavior

Let $B'=B$ when SUB=0 and $B'=M-1-B$ when SUB=1. The shared addition is $T=A+B'+\mathrm{C\_IN}$; OUT is T modulo M and CARRY_OUT is `[T >= M]`.

| SUB | C_IN | Result before wrapping |
| ---: | ---: | --- |
| 0 | 0 | A + B |
| 0 | 1 | A + B + 1 |
| 1 | 1 | A − B |
| 1 | 0 | A − B − 1 |

SUB controls inversion and does not supply carry-in in the extended contract. For subtraction, carry is `[A >= B + (1 − C_IN)]`, evaluated without W-bit truncation. Signed overflow uses the effective operand and result signs: `NOT(A_sign XOR B'_sign) AND (A_sign XOR OUT_sign)`. The [integer interface](2.7.md#271-addsubw) supplies SUB as the initial carry instead.

#### C++ example

This binary reference is parameterized by W = 8, 16 or 32. Inputs must fit their documented pin widths. It omits propagation delays and X/Z values.

```cpp
template<unsigned W>
struct AddSubResult {
    std::uint32_t OUT;
    bool CARRY_OUT;
    bool OVERFLOW;
};

template<unsigned W>
AddSubResult<W> addsub_ref(
    std::uint32_t a, std::uint32_t b, bool sub, bool c_in) {
    const auto effective_b = static_cast<std::uint32_t>(
        b ^ (sub ? WordReference<W>::mask : 0x00u));
    const auto sum = adder_ref<W>(a, effective_b, c_in);
    const bool same_sign = ((a ^ effective_b) & WordReference<W>::sign) == 0;
    const bool result_changed_sign = ((a ^ sum.Sum) & WordReference<W>::sign) != 0;
    return {sum.Sum, sum.Cout, same_sign && result_changed_sign};
}
```

#### Unknown inputs

Conditional inversion, carry propagation and sign logic use four-state gates. Unknown SUB or C_IN follows those gates rather than an assumed Boolean value. The C++ reference covers binary values only.

### Implementation

#### Structural implementation

W XOR gates form B′. One `Adder<W>` computes A + B′ + C_IN, using the selected topology. Splitters/joiners expose the sign bits and assemble the operand/result words. Sign XOR/NOT/AND logic produces overflow without a separate subtractor. The extended sign equation is retained independently of the integer contract's carry-into-sign equation.

#### Behavioral implementation

The settled-value rules are parameterized by W and addition topology in `ExtendedALUValueModel<W, Topology>` (`WordALUValueModel.hpp`). They use the same four-state gates, masks, carry construction and movement stages as the structural circuit. Word loops use W, the sign is bit W−1, and the shifter has log₂(W) stages. Operation codes and local selector sizes are control widths and remain independent of W.

A catalog behavioral factory is available only for its verified configuration. The eight-bit ripple adapter uses these shared rules with its characterized delay table; other configurations on this page remain structural. The value model alone does not supply timing or enable compact fidelity. `ALUWidthContractTest` compares both topologies at 8/16/32 bits against the gates and an independent binary reference; `ExtendedALUFidelityContractTest` retains the compact-fidelity checks for those configurations.

For `A = B = 0xFF`, `SUB = 1`, and `C_IN = 0`, the calculation is `255 - 255 - 1 = -1` under unsigned arithmetic, so it requires a borrow. Under signed interpretation it is `-1 - (-1) - 1 = -1`, which does not overflow.

## 2.1.5. `ArithmeticUnit<W>`

### IO pins

| Pin | Direction | Width | Description |
| --- | --- | ---: | --- |
| `A`, `B` | Input | W each | Primary and secondary operands |
| `OP` | Input | 3 | Local arithmetic selector |
| `C_IN` | Input | 1 | Carry/no-borrow input for ADC/SBC |
| `OUT` | Output | W | Selected arithmetic result |
| `CARRY` | Output | 1 | Carry or no-borrow |
| `OVERFLOW` | Output | 1 | Signed overflow |
| `INVALID_OP` | Output | 1 | Local opcode 7 |

### Behavior

One shared `AddSub<W>` performs the selected operation. Results wrap modulo M.

| Local OP | Operation | Result before wrapping | Carry input used? |
| ---: | --- | --- | --- |
| 0 | ADD | A + B | No |
| 1 | ADC | A + B + C_IN | Yes |
| 2 | SUB | A − B | No |
| 3 | SBC | A − B − (1 − C_IN) | Yes |
| 4 | INC | A + 1 | No |
| 5 | DEC | A − 1 | No |
| 6 | NEG | 0 − A | No |
| 7 | Reserved | OUT=0, CARRY=0, OVERFLOW=0, INVALID_OP=1 | No |

<a id="arithmetic-flags"></a>

For INC, carry means A=M−1 and overflow means A=S−1. For DEC, no-borrow means A≠0 and overflow means A=S. For NEG, no-borrow means A=0 and overflow means A=S. The other overflow cases follow the signed mathematical result's range. `INVALID_OP` reports an encoding, not uncertainty in the operands.

The complete extended ALU uses five-bit OP; its arithmetic encodings 0–6 match this local map. Other operation groups are decoded separately.

#### C++ example

This binary reference is parameterized by W = 8, 16 or 32. Inputs must fit their documented pin widths. It omits propagation delays and X/Z values.

```cpp
template<unsigned W>
struct ArithmeticResult {
    std::uint32_t OUT;
    bool CARRY;
    bool OVERFLOW;
    bool INVALID_OP;
};

template<unsigned W>
ArithmeticResult<W> arithmetic_ref(
    std::uint32_t a, std::uint32_t b, std::uint32_t op, bool c_in) {
    std::uint32_t x = a;
    std::uint32_t y = b;
    bool sub = false;
    bool carry_in = false;

    switch (op) {
    case 0x00: break;                                      // ADD
    case 0x01: carry_in = c_in; break;                     // ADC
    case 0x02: sub = true; carry_in = true; break;          // SUB
    case 0x03: sub = true; carry_in = c_in; break;          // SBC
    case 0x04: y = 0; carry_in = true; break;               // INC
    case 0x05: y = 1; sub = true; carry_in = true; break;   // DEC
    case 0x06: x = 0; y = a; sub = true;
               carry_in = true; break;                    // NEG
    default: return {0, false, false, true};
    }

    const auto result = addsub_ref<W>(x, y, sub, carry_in);
    return {result.OUT, result.CARRY_OUT, result.OVERFLOW, false};
}
```

#### Unknown inputs

Operand multiplexers isolate ignored inputs. NEG ignores B and C_IN; INC/DEC ignore B. Reserved OP masks result/carry/overflow to zero. Unknown selectors follow the gate-built multiplexers.

### Implementation

#### Structural implementation

Opcode-controlled operand and carry multiplexers, constants, one `AddSub<W>` and reserved-operation masks form the circuit. SUB uses initial carry 1; SBC uses C_IN. INC selects B=0 and carry 1; DEC selects B=1, SUB=1 and carry 1; NEG selects A=0, B=the original A, SUB=1 and carry 1. The adder topology comes from `ALUConfig`.

#### Behavioral implementation

The settled-value rules are parameterized by W and addition topology in `ExtendedALUValueModel<W, Topology>` (`WordALUValueModel.hpp`). They use the same four-state gates, masks, carry construction and movement stages as the structural circuit. Word loops use W, the sign is bit W−1, and the shifter has log₂(W) stages. Operation codes and local selector sizes are control widths and remain independent of W.

A catalog behavioral factory is available only for its verified configuration. The eight-bit ripple adapter uses these shared rules with its characterized delay table; other configurations on this page remain structural. The value model alone does not supply timing or enable compact fidelity. `ALUWidthContractTest` compares both topologies at 8/16/32 bits against the gates and an independent binary reference; `ExtendedALUFidelityContractTest` retains the compact-fidelity checks for those configurations.

## 2.1.6. `ParallelPrefixAdder<W>`

### IO pins

| Pin | Direction | Width | Description |
| --- | --- | ---: | --- |
| `A`, `B` | Input | W each | Operand patterns |
| `Cin` | Input | 1 | Carry entering bit 0 |
| `Sum` | Output | W | Low W bits of A+B+Cin |
| `Cout` | Output | 1 | Carry leaving bit W−1 |
| `C7`, `C15` or `C31` | Output | 1 | Carry entering the sign bit, named for the instantiated width |

### Behavior

The result is the same binary addition contract as `Adder<W>`: `Sum = (A+B+Cin) mod 2^W`, with `Cout` indicating an unsigned overflow. The extra carry into the sign bit supports signed-overflow circuitry. W is 8, 16 or 32. The component is combinational and has no clock, start signal or retained state.

#### C++ example

The binary reference describes the settled values independently of the carry topology. `adder_ref<W>` is defined in §2.1.3. Inputs must fit W bits.

```cpp
template<unsigned W>
struct PrefixAdderResult {
    std::uint32_t Sum;
    bool Cout;
    bool CarryIntoSign;
};

template<unsigned W>
PrefixAdderResult<W> prefix_adder_ref(std::uint32_t a, std::uint32_t b, bool cin) {
    const auto sum = adder_ref<W>(a, b, cin);
    const auto low_mask = WordReference<W>::sign - 1;
    const bool carry_into_sign = ((a & low_mask) + (b & low_mask) + cin)
                                  >= WordReference<W>::sign;
    return {sum.Sum, sum.Cout, carry_into_sign};
}
```

#### Unknown inputs

Bit propagate/generate and group-combination gates apply four-state XOR/AND/OR rules. An unknown operand or carry can leave some outputs known. Z entering a logic gate is treated as unknown. No binary integer shortcut defines these cases.

### Implementation

#### Structural implementation

Each bit computes `pᵢ = Aᵢ XOR Bᵢ` and `gᵢ = Aᵢ AND Bᵢ` with a half adder. A carry group is the transformation `c_out = G OR (P AND c_in)`. Adjacent groups combine as `G = G_high OR (P_high AND G_low)` and `P = P_high AND P_low`.

Levels at distances 1, 2, 4, … construct every carry prefix in log₂(W) levels. The original bit propagates and the resulting carries produce `Sum`; the last group produces `Cout`. W=8/16/32 therefore has 3/4/5 prefix levels. Ripple carry instead has W dependent full-adder carry stages. Gate delays, fanout and the surrounding ALU still determine the final settling bound.

`Adder<W>(name, AdderTopology::ParallelPrefix)` wraps this component and exposes only `A`, `B`, `Cin`, `Sum` and `Cout`. `ALU<W>` uses that optimized wrapper by default. An explicit `ALUConfig` can select ripple carry for inspection or timing comparison. Ripple carry is selected explicitly with `AdderTopology::Ripple`.
