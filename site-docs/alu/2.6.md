# § 2.6. Complete ALU

`ALU<W>` joins the units of § 2.1–2.5 into one combinational ALU: 29 operations selected by a five-bit `OP`, a carry input for multi-word arithmetic, and four result flags. W is the only parameter. Addition uses the parallel-prefix adder. Multiplication and division are separate iterative units.

The RV32I cores use a different, smaller ALU without flags or a carry input: [`RV32IALU`](../rv32i/4.3/alu.md), built from the same adder and zero detector.

| Component | Description | Structural | Behavioral |
| --- | --- | :---: | :---: |
| `ALUControlDecoder` | Operation decoding; independent of the operand width | Yes | Yes |
| `ALUResultSelector<W>` | OR-combination of six enabled result sources | Yes | Yes |
| `ALU<W>` | 29-operation ALU with carry input and result flags | Yes | No |

W is **8, 16 or 32**. The fidelity columns describe the recorded configuration of each section: the decoder, the eight-bit result selector and the 16-bit ALU. `ALU<8>` also has a compact form; `ALU<16>` and `ALU<32>` are structural only.

```c++
builder.add(circuit::families::alu(16), "ALU");    // as a child: the build profile picks the fidelity
```

Headers are in `include/modules/composite/`. Compact forms exist for every unit at W = 8, for both adders at every width, and for `ZeroDetect<32>`; other configurations are structural. Python builds the same components with `create_word_component(unit, name, width, fidelity)`, where `unit` is `alu`, `add-sub`, `arithmetic`, `logic`, `shift`, `compare`, `flags`, `result`, `ripple-adder`, `prefix-adder` or `zero`, and `create_alu_control(name)`. An unsupported width or fidelity is rejected.

Pin names follow one rule: `A` and `B` are operands, `OUT` is the result word, `C_IN` and `C_OUT` are carry ports, and `ZERO`, `NEGATIVE`, `CARRY` and `OVERFLOW` are flags. The one-bit cells of § 2.1.1–2.1.2 keep their own names.

## 2.6.1. `ALUControlDecoder`

### IO pins

| Pin | Direction | Width | Description |
| --- | --- | ---: | --- |
| `OP` | Input | 5 | Complete ALU opcode |
| `LOCAL_OP` | Output | 3 | OP[2:0] for logic and shifts |
| `ARITH_OP` | Output | 3 | Arithmetic selector; forced to SUB=2 for comparisons |
| `COMPARE_OP` | Output | 3 | OP−21 during comparisons; otherwise zero |
| `ARITHMETIC_ENABLE`, `LOGIC_ENABLE`, `SHIFT_ENABLE`, `COMPARE_ENABLE` | Output | 1 each | Result group enables |
| `PASS_A_ENABLE`, `PASS_B_ENABLE` | Output | 1 each | Operand pass-through enables |
| `INVALID_OP` | Output | 1 | Reserved opcode |

### Behavior

Arithmetic enables cover 0–6, logic 8–14, shifts 16–20, comparisons 21–27 and operand passes 28/29. At most one result source is enabled for a binary opcode. CLEAR=30 and reserved 7/15/31 disable all sources; only the reserved codes assert INVALID_OP. Comparisons request arithmetic SUB through ARITH_OP while leaving ARITHMETIC_ENABLE low.

The decoder has no width parameter; one decoder serves every `ALU<W>`.

#### C++ example

This binary control reference has no operand width. OP must fit five bits; it omits propagation delays and X/Z values.

```cpp
#include <cstdint>
#include <stdexcept>

struct ALUControl {
    std::uint8_t LOCAL_OP, ARITH_OP, COMPARE_OP;
    bool ARITHMETIC_ENABLE, LOGIC_ENABLE, SHIFT_ENABLE, COMPARE_ENABLE;
    bool PASS_A_ENABLE, PASS_B_ENABLE, INVALID_OP;
};

ALUControl alu_control_ref(std::uint8_t op) {
    if (op > 31) throw std::invalid_argument("OP must fit five bits");
    const bool compare = op >= 21 && op <= 27;
    return {
        static_cast<std::uint8_t>(op & 7),
        static_cast<std::uint8_t>(compare ? 2 : op & 7),
        static_cast<std::uint8_t>(compare ? op - 21 : 0),
        op <= 6, op >= 8 && op <= 14, op >= 16 && op <= 20, compare,
        op == 28, op == 29, op == 7 || op == 15 || op == 31
    };
}
```

#### Unknown inputs

Unknown OP bits follow the decoder's gate equations. INVALID_OP is an encoding predicate and does not certify that OP is binary. LOCAL_OP directly forwards its three bits, including Z.

### Implementation

#### Structural implementation

A `Decoder<5>` with enable high feeds OR networks for group enables and invalid codes. Splitter/joiner wiring forwards the low opcode bits. Three muxes override arithmetic selection for comparisons; OR networks form the local comparison code.

#### Behavioral implementation

The compact form computes the decoder's settled outputs in one step with the same Boolean factoring, so X and Z inputs give the same outputs as the gates. It runs on delays proven on the gates and does not reproduce intermediate glitches.

## 2.6.2. `ALUResultSelector<W>`

### IO pins

| Pin | Direction | Width | Description |
| --- | --- | ---: | --- |
| `ARITHMETIC_RESULT`, `LOGIC_RESULT`, `SHIFT_RESULT`, `COMPARE_RESULT` | Input | W each | Operation-unit results |
| `A`, `B` | Input | W each | Operand pass-through sources |
| `ARITHMETIC_ENABLE`, `LOGIC_ENABLE`, `SHIFT_ENABLE`, `COMPARE_ENABLE` | Input | 1 each | Operation-unit enables |
| `PASS_A_ENABLE`, `PASS_B_ENABLE` | Input | 1 each | Pass-through enables |
| `OUT` | Output | W | Bitwise OR of enabled sources |

### Behavior

Each source is AND-masked by its independent enable, then OR-combined. One enable selects that source; no enables produce zero; multiple enables produce the bitwise OR of those sources. There is no priority or invalid-selection output.

#### C++ example

This binary reference is parameterized by W = 8, 16 or 32. Inputs must fit their documented pin widths. It omits propagation delays and X/Z values.

```cpp
#include <array>
#include <cstdint>

template<unsigned W>
std::uint32_t alu_result_selector_ref(
    const std::array<std::uint32_t, 6>& sources,
    const std::array<bool, 6>& enables) {
    std::uint32_t out = 0;
    for (unsigned i = 0; i < sources.size(); ++i)
        if (enables[i]) out |= sources[i];
    return out;
}
```

#### Unknown inputs

Low enables mask X/Z source bits. Active unknown values and unknown enables follow AND/OR logic. Z data is not forwarded as high impedance through a logic gate.

### Implementation

#### Structural implementation

Six splitters provide the candidate bits. Per output bit, six AND gates mask sources and five OR gates combine them; a joiner assembles OUT. Operation units remain combinationally active regardless of selection.

#### Behavioral implementation

The compact form, available at W = 8, computes the settled outputs of these gates in one step. It keeps the gates' Boolean factoring, so X and Z inputs give the same outputs as the structural circuit, and it runs on delays proven on that circuit ([delay model](../timing.md)).

## 2.6.3. `ALU<W>`

### IO pins

| Pin | Direction | Width | Description |
| --- | --- | ---: | --- |
| `A`, `B` | Input | W each | Operands; B also supplies shift distance |
| `OP` | Input | 5 | Operation code |
| `C_IN` | Input | 1 | ADC/SBC input; zero-distance shift carry |
| `OUT` | Output | W | Selected result |
| `ZERO`, `NEGATIVE` | Output | 1 each | Result zero and binary sign |
| `CARRY`, `OVERFLOW` | Output | 1 each | Qualified source flags |
| `INVALID_OP` | Output | 1 | Reserved opcode |

### Behavior

Operands and `OUT` are W-bit patterns. Arithmetic wraps modulo $2^W$; signed operations interpret a pattern as two's complement in $-2^{W-1}$ through $2^{W-1}-1$. Let $s(x)$ denote that signed interpretation and $n=B\mathbin{\&}(W-1)$ the effective shift distance.

#### Opcode map

| `OP` | Operation | `OUT` |
| --- | --- | --- |
| `0x00` | `ADD` | `A + B` |
| `0x01` | `ADC` | `A + B + C_IN` |
| `0x02` | `SUB` | `A - B` |
| `0x03` | `SBC` | `A - B - (1 - C_IN)` |
| `0x04` | `INC` | `A + 1` |
| `0x05` | `DEC` | `A - 1` |
| `0x06` | `NEG` | `0 - A` |
| `0x07` | Reserved | `0x00`; `INVALID_OP = 1` |
| `0x08` | `AND` | `A AND B`, bitwise |
| `0x09` | `OR` | `A OR B`, bitwise |
| `0x0A` | `XOR` | `A XOR B`, bitwise |
| `0x0B` | `NOT` | Bitwise complement of `A` |
| `0x0C` | `NAND` | Bitwise complement of `A AND B` |
| `0x0D` | `NOR` | Bitwise complement of `A OR B` |
| `0x0E` | `XNOR` | Bitwise complement of `A XOR B` |
| `0x0F` | Reserved | `0x00`; `INVALID_OP = 1` |
| `0x10` | `SLL` | Shift `A` left by `n`, zero fill |
| `0x11` | `SRL` | Shift `A` right by `n`, zero fill |
| `0x12` | `SRA` | Shift `A` right by `n`, sign fill |
| `0x13` | `ROL` | Rotate `A` left by `n` |
| `0x14` | `ROR` | Rotate `A` right by `n` |
| `0x15` | `EQ` | `0x01` if `A == B`, otherwise `0x00` |
| `0x16` | `SLTU` | `0x01` if unsigned `A < B`, otherwise `0x00` |
| `0x17` | `SLT` | `0x01` if `s(A) < s(B)`, otherwise `0x00` |
| `0x18` | `MINU` | Smaller unsigned operand |
| `0x19` | `MAXU` | Larger unsigned operand |
| `0x1A` | `MINS` | Operand with smaller signed value |
| `0x1B` | `MAXS` | Operand with larger signed value |
| `0x1C` | `PASS_A` | `A` |
| `0x1D` | `PASS_B` | `B` |
| `0x1E` | `CLEAR` | `0x00`; `INVALID_OP = 0` |
| `0x1F` | Reserved | `0x00`; `INVALID_OP = 1` |

Min/max operations return the original operand pattern, not a predicate or magnitude. Rotations operate on W bits, excluding carry. The full operation details are in [arithmetic](2.1.md), [logic](2.2.md), [shifts and rotations](2.3.md), and [comparison and selection](2.4.md).

#### Flags and ignored inputs

`ZERO = [OUT == 0]` and `NEGATIVE = OUT[W−1]` for every binary result, including predicates and reserved operations. A false comparison therefore sets `ZERO = 1`; a true comparison returns `0x01` and sets `ZERO = 0`.

| Operation group | `CARRY` | `OVERFLOW` |
| --- | --- | --- |
| Arithmetic (`0x00`–`0x06`) | Carry-out for addition; 1 means **no borrow** for subtraction | Signed result before wrapping is outside −2^(W−1)…2^(W−1)−1 |
| Shift/rotate (`0x10`–`0x14`), `n > 0` | Last bit shifted/rotated out | 0 |
| Shift/rotate (`0x10`–`0x14`), `n = 0` | `C_IN` | 0 |
| Logic, comparison, min/max, pass, clear, reserved | 0 | 0 |

The arithmetic flag rules for `INC`, `DEC`, and `NEG` are specified in [2.1](2.1.md#arithmetic-flags). In particular, `NEG` sets carry only for `A = 0`; this ALU uses the no-borrow convention consistently.

For known opcodes, ignored inputs are isolated from the settled outputs:

- `B` is ignored by `INC`, `DEC`, `NEG`, `NOT`, and `PASS_A`.
- `A` is ignored by `PASS_B`; both operands are ignored by `CLEAR` and reserved operations.
- Shifts and rotations ignore `B[W−1:log₂(W)]`, even when those bits are unknown.
- `C_IN` is used only by `ADC`, `SBC`, and zero-distance shifts/rotates. In particular, ordinary subtraction and all comparisons ignore it.

Reserved opcodes produce `OUT = 0`, `ZERO = 1`, `NEGATIVE = CARRY = OVERFLOW = 0`, and `INVALID_OP = 1`. `CLEAR` produces the same result and flags except `INVALID_OP = 0`. For a supported, known opcode, `INVALID_OP = 0` even when an operand is unknown or arithmetic overflows.

#### C++ example

This binary reference is parameterized by W = 8, 16 or 32. Inputs must fit their documented pin widths. It omits propagation delays and X/Z values.

```cpp
template<unsigned W>
struct ALUResult {
    std::uint32_t OUT;
    bool ZERO;
    bool NEGATIVE;
    bool CARRY;
    bool OVERFLOW;
    bool INVALID_OP;
};

template<unsigned W>
ALUResult<W> alu_ref(
    std::uint32_t a, std::uint32_t b, std::uint32_t op, bool c_in) {
    const bool arithmetic = op <= 0x06;
    const bool logic = op >= 0x08 && op <= 0x0E;
    const bool shift = op >= 0x10 && op <= 0x14;
    const bool comparison = op >= 0x15 && op <= 0x1B;
    const bool transfer = op >= 0x1C && op <= 0x1E;
    const bool invalid = !(arithmetic || logic || shift || comparison || transfer);

    std::uint32_t out = 0;
    bool arith_carry = false, arith_overflow = false, shift_carry = false;
    if (arithmetic || comparison) {
        const auto local_op = static_cast<std::uint32_t>(comparison ? 2 : op);
        const auto r = arithmetic_ref<W>(a, b, local_op, c_in);
        arith_carry = r.CARRY;
        arith_overflow = r.OVERFLOW;
        out = comparison
            ? compare_select_ref<W>(a, b, r.OUT, r.CARRY, r.OVERFLOW,
                                  static_cast<std::uint32_t>(op - 0x15))
            : r.OUT;
    } else if (logic) {
        out = logic_ref<W>(a, b, static_cast<std::uint32_t>(op - 0x08));
    } else if (shift) {
        const auto r = shift_ref<W>(a, b, static_cast<std::uint32_t>(op - 0x10), c_in);
        out = r.OUT;
        shift_carry = r.CARRY;
    } else if (op == 0x1C) {
        out = a;
    } else if (op == 0x1D) {
        out = b;
    }
    const auto f = flags_ref<W>(out, arithmetic, shift,
                              arith_carry, arith_overflow, shift_carry);
    return {out, f.ZERO, f.NEGATIVE, f.CARRY, f.OVERFLOW, invalid};
}
```

#### Unknown inputs

The structural gates determine four-state behavior; the C++ example does not. Known operation selection masks inactive result paths, so unknown data in an unused path does not automatically make `OUT` unknown. For example, `CLEAR` and reserved opcodes still produce their defined zero result with unknown data and carry inputs, and `AND` with an all-zero operand produces zero despite unknown bits in the other operand.

An `X`/`Z` bit that affects the selected computation follows its gates' propagation rules. `ZERO` can be unknown for a partially unknown result with no known 1. A high-impedance operand bit passing through logic is treated as unknown, not preserved as a high-impedance output.

An opcode containing `X` or `Z` is not automatically a reserved encoding. Decoder and selection gates determine the outputs; `INVALID_OP` is not an input-validity checker. The contract test specifically checks that an entirely unknown/high-impedance opcode produces `INVALID_OP = X`, without asserting a complete output word for that case.

The compact `ALU<8>` runs on delays proven on its gates, one set per operation code, so a quick operation does not wait for the slowest one. It does not reproduce intermediate gate glitches.

### Implementation

#### Structural implementation

The structural groups are `CONTROL` (`ALUControlDecoder`), `ARITHMETIC` (`ArithmeticUnit<W>`), `LOGIC`, `SHIFTER`, `COMPARE_SELECT`, `RESULT_SELECT` and `FLAGS`. The arithmetic unit owns the one add/subtract circuit; its difference, carry and overflow also feed comparison. Result selection feeds the zero and sign flags; the operation-group enables qualify carry and overflow.

#### Behavioral implementation
