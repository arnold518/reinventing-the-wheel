# § 2.5. Flags

`ALUFlagUnit<W>` with `Operations::Extended` derives result flags and qualifies arithmetic/shift status. Flags are combinational observations, not stored condition codes. The [integer flag contract](2.7.md#277-aluflagunitw) qualifies arithmetic flags differently and has a different sign routing rule.

| Component | Description | Structural | Behavioral |
| --- | --- | :---: | :---: |
| `ALUFlagUnit<W>` | Zero/sign detection and enabled carry/overflow | Yes | Yes |

W is **8, 16 or 32**. The behavioral column describes the recorded eight-bit ripple configuration; other word widths/topologies use structural circuits unless their catalog family provides a matching behavioral factory. The binary C++ references take W as a parameter; the tables record their stated concrete eight-bit configuration. [Configuration and family selection](../components/word-components.md) specifies construction.

## 2.5.1. `ALUFlagUnit<W>`

### IO pins

| Pin | Direction | Width | Description |
| --- | --- | ---: | --- |
| `RESULT` | Input | W | Final selected result |
| `ARITHMETIC`, `SHIFT` | Input | 1 each | Arithmetic/shift flag enables |
| `ARITH_CARRY`, `ARITH_OVERFLOW` | Input | 1 each | Arithmetic source flags |
| `SHIFT_CARRY` | Input | 1 | Shifter source carry |
| `ZERO`, `NEGATIVE` | Output | 1 each | Result zero and binary sign |
| `CARRY`, `OVERFLOW` | Output | 1 each | Enabled source flags |

### Behavior

For binary inputs, ZERO=[RESULT==0], NEGATIVE=RESULT[W−1], CARRY=(ARITHMETIC AND ARITH_CARRY) OR (SHIFT AND SHIFT_CARRY), and OVERFLOW=ARITHMETIC AND ARITH_OVERFLOW.

Both enables low clear carry/overflow. Both high OR the carry sources; there is no priority. The complete extended ALU uses mutually exclusive enables. Comparison/min/max operations clear these enables. Persistent condition codes require a separate register.

#### C++ example

This binary reference is parameterized by W = 8, 16 or 32. Inputs must fit their documented pin widths. It omits propagation delays and X/Z values.

```cpp
#include <cstdint>

struct FlagsResult {
    bool ZERO;
    bool NEGATIVE;
    bool CARRY;
    bool OVERFLOW;
};

template<unsigned W>
FlagsResult flags_ref(
    std::uint32_t result, bool arithmetic, bool shift,
    bool arith_carry, bool arith_overflow, bool shift_carry) {
    return {
        result == 0,
        (result & WordReference<W>::sign) != 0,
        (arithmetic && arith_carry) || (shift && shift_carry),
        arithmetic && arith_overflow,
    };
}
```

#### Unknown inputs

Zero detection masks unknowns when any result bit is known one. Sign passes through OR with zero, so either X or Z in RESULT[W−1] produces NEGATIVE=X. Low enables mask unknown source flags; all remaining cases follow four-state AND/OR gates. This sign rule differs from the integer contract's direct rewire.

### Implementation

#### Structural implementation

`ZERO_DETECT` is `ZeroDetect<W>`. `RESULT_SPLIT` exposes the sign; `SIGN` ORs it with zero. Two AND gates mask carry sources, an OR combines them, and another AND qualifies overflow. There is no flag storage or clock.

#### Behavioral implementation

The settled-value rules are parameterized by W and addition topology in `ExtendedALUValueModel<W, Topology>` (`WordALUValueModel.hpp`). They use the same four-state gates, masks, carry construction and movement stages as the structural circuit. Word loops use W, the sign is bit W−1, and the shifter has log₂(W) stages. Operation codes and local selector sizes are control widths and remain independent of W.

A catalog behavioral factory is available only for its verified configuration. The eight-bit ripple adapter uses these shared rules with its characterized delay table; other configurations on this page remain structural. The value model alone does not supply timing or enable compact fidelity. `ALUWidthContractTest` compares both topologies at 8/16/32 bits against the gates and an independent binary reference; `ExtendedALUFidelityContractTest` retains the compact-fidelity checks for those configurations.
