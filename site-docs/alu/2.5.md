# § 2.5. Flags

`ALUFlagUnit<W>` derives result flags and qualifies arithmetic and shift status. Flags are combinational outputs, not stored condition codes.

| Component | Description | Structural | Behavioral |
| --- | --- | :---: | :---: |
| `ALUFlagUnit<W>` | Zero/sign detection and enabled carry/overflow | Yes | Yes |

W is **8, 16 or 32**. The fidelity columns hold at every width: each unit has a structural and a compact form at 8, 16 and 32 bits. The C++ references take W as a template parameter. [Construction and selection](2.6.md#construction-and-selection) describes construction.

## 2.5.1. `ALUFlagUnit<W>`

### IO pins

| Pin | Direction | Width | Description |
| --- | --- | ---: | --- |
| `RESULT` | Input | W | Final selected result |
| `ARITHMETIC`, `SHIFT` | Input | 1 each | Arithmetic/shift flag enables |
| `ARITH_CARRY`, `ARITH_OVERFLOW` | Input | 1 each | Arithmetic source flags |
| `SHIFT_CARRY` | Input | 1 | Shifter source carry |
| `ZERO`, `NEGATIVE` | Output | 1 each | Result zero and binary sign |
| `CARRY`, `OVERFLOW` | Output | 1 each | Enabled source flags |

### Behavior

For binary inputs, ZERO=[RESULT==0], NEGATIVE=RESULT[W−1], CARRY=(ARITHMETIC AND ARITH_CARRY) OR (SHIFT AND SHIFT_CARRY), and OVERFLOW=ARITHMETIC AND ARITH_OVERFLOW.

Both enables low clear carry/overflow. Both high OR the carry sources; there is no priority. The complete ALU drives mutually exclusive enables. Comparison/min/max operations clear these enables. Persistent condition codes require a separate register.

#### C++ example

This binary reference is parameterized by W = 8, 16 or 32. Inputs must fit their documented pin widths. It omits propagation delays and X/Z values.

```cpp
#include <cstdint>

struct FlagsResult {
    bool ZERO;
    bool NEGATIVE;
    bool CARRY;
    bool OVERFLOW;
};

template<unsigned W>
FlagsResult flags_ref(
    std::uint32_t result, bool arithmetic, bool shift,
    bool arith_carry, bool arith_overflow, bool shift_carry) {
    return {
        result == 0,
        (result & WordReference<W>::sign) != 0,
        (arithmetic && arith_carry) || (shift && shift_carry),
        arithmetic && arith_overflow,
    };
}
```

#### Unknown inputs

Zero detection masks unknowns when any result bit is known one. Sign passes through OR with zero, so either X or Z in RESULT[W−1] produces NEGATIVE=X. Low enables mask unknown source flags; all remaining cases follow four-state AND/OR gates.

### Implementation

#### Structural implementation

`ZERO_DETECT` is `ZeroDetect<W>`. `RESULT_SPLIT` exposes the sign; `SIGN` ORs it with zero. Two AND gates mask carry sources, an OR combines them, and another AND qualifies overflow. There is no flag storage or clock.

#### Behavioral implementation

The compact form, available at W = 8, 16 and 32, computes the settled outputs of these gates in one step. It keeps the gates' Boolean factoring, so X and Z inputs give the same outputs as the structural circuit, and it runs on delays proven on that circuit ([delay model](../basic/1.2.md)).
