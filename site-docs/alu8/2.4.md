# § 2.4. Comparison and Selection

`ALU8` reuses its arithmetic subtraction path for comparisons. `ZeroDetect8` reduces a word to a zero predicate; `CompareSelect8` consumes subtraction outputs to produce predicates or select one of the original operands.

| Component | Description | Structural | Behavioral |
| --- | --- | :---: | :---: |
| `ZeroDetect8` | Reports whether an eight-bit word is zero through a one-bit predicate | Yes | Yes |
| `CompareSelect8` | Uses subtraction results and flags to produce equality/less-than predicates or signed/unsigned min/max selections | Yes | Yes |

These columns indicate registered simulator implementations; the simplified C++ examples below are not counted.

The bit numbering, signed interpretation, and no-borrow convention from [2.1. Arithmetic Components](2.1.md) apply here. Both components are combinational, with no clock or stored flags. The simplified **C++ examples** describe binary behavior, not the simulator implementation; they omit propagation delays and `X`/`Z` handling and can be compiled together in the order shown.

## 2.4.1. `ZeroDetect8`

`ZeroDetect8` asserts a one-bit output only when every input bit is zero. The same component is reused for equality detection and the complete ALU's result-zero flag.

### IO pins

| Pin | Direction | Width | Description |
| --- | --- | ---: | --- |
| `A` | Input | 8 | Word to inspect |
| `ZERO` | Output | 1 | 1 when all eight input bits are zero |

### Behavior

For binary inputs,

$$
\mathrm{ZERO} = [A = 0]
= \neg(A_0 \lor A_1 \lor \cdots \lor A_7).
$$

`ZERO` is an active-high predicate, not an eight-bit result. There is no signed/unsigned distinction: only the all-zero bit pattern produces 1.

#### C++ example

```cpp
#include <cstdint>

bool zero_detect8_ref(std::uint8_t a) {
    return a == 0;
}
```

#### Unknown inputs and timing

| Input condition | Settled `ZERO` |
| --- | --- |
| Every bit is 0 | 1 |
| At least one bit is 1, regardless of other `X`/`Z` bits | 0 |
| No bit is 1, and at least one bit is `X` or `Z` | `X` |

`Z` denotes high impedance and is interpreted as unknown by the OR/NOT gates. The component's `ZERO` output never denotes high impedance.

The OR gates form a balanced three-level reduction tree. Every input bit crosses the same number of OR gates before the final inversion. The predicate can still change while inputs propagate; no single component latency is declared. The C++ example describes only settled binary behavior.

### Implementation

#### Structural implementation

| Internal component | Count | Connection |
| --- | ---: | --- |
| `BitSplitter<8>` | 1 | Split `A` into bits 0–7 |
| `ORGate` | 7 | Reduce the bits to an any-one predicate |
| `NOTGate` | 1 | Invert the reduction into `ZERO` |

`OR0`–`OR3` combine adjacent input-bit pairs; `OR4` and `OR5` combine pairs of those results; `OR6` combines the two halves. `OR6.OUT` feeds `NOT_ZERO.IN`; `NOT_ZERO.OUT` drives the external `ZERO` pin.

#### Behavioral implementation

`Behavioral8<ZeroDetect8>` calls `zero`, which OR-reduces the eight four-state input values and inverts the result. A known 1 establishes `ZERO = 0`; without a known 1, an `X` or `Z` prevents the result from being known.

The evaluator is defined in [ALU8Behavioral.cpp](https://github.com/arnold518/reinventing-the-wheel/blob/github-pages/src/modules/composite/ALU8Behavioral.cpp); its value functions are in [ALU8ValueModel.hpp](https://github.com/arnold518/reinventing-the-wheel/blob/github-pages/src/modules/composite/ALU8ValueModel.hpp). It retains the public pins and schedules outputs with one abstract delay tick, without internal circuit objects or gate-propagation glitches.

The recorded scenario runs against both implementations in CTest. [ALU8FidelityContractTest](https://github.com/arnold518/reinventing-the-wheel/blob/github-pages/src/tests/ALU8BehavioralTests.cpp) checks binary/X/Z settled-output equivalence against the structural circuit. The example table uses the default structural run; its checkpoint times need not match the behavioral run.

## 2.4.2. `CompareSelect8`

`CompareSelect8` derives comparison decisions from an externally supplied subtraction result and flags. It returns an eight-bit predicate or selects `A` or `B`; it contains no subtractor.

### IO pins

| Pin | Direction | Width | Description |
| --- | --- | ---: | --- |
| `A` | Input | 8 | First original operand, available for min/max selection |
| `B` | Input | 8 | Second original operand, available for min/max selection |
| `DIFF` | Input | 8 | Low eight bits of `A - B` |
| `CARRY_IN` | Input | 1 | Carry-out of that subtraction; 1 means no unsigned borrow |
| `OVERFLOW_IN` | Input | 1 | Signed overflow of that subtraction |
| `OP` | Input | 3 | Local comparison/selection opcode |
| `OUT` | Output | 8 | Predicate encoded as `0x00`/`0x01`, or the selected operand |

`CARRY_IN` is a subtraction **output supplied to this component**, not the incoming carry/borrow operand of `AddSub8`. There is no `C_IN` pin and no `ZERO`, `CARRY`, `OVERFLOW`, or `INVALID_OP` output on `CompareSelect8`.

### Behavior

For the results to represent comparisons of the supplied `A` and `B`, the caller must provide a consistent subtraction:

$$
\begin{aligned}
\mathrm{DIFF} &= (A-B) \bmod 256, \\
\mathrm{CARRY\_IN} &= [A \geq B], \\
\mathrm{OVERFLOW\_IN} &= [s(A)-s(B) \notin [-128,127]].
\end{aligned}
$$

The internal decisions are

$$
E = [\mathrm{DIFF}=0], \qquad
L_u = \neg\mathrm{CARRY\_IN}, \qquad
L_s = \mathrm{DIFF}_7 \oplus \mathrm{OVERFLOW\_IN}.
$$

`L_s` corrects the sign of a wrapped subtraction when signed overflow occurs. A sign-bit test alone is not a signed comparison.

| Local `OP` | Operation | `OUT` | Decision inputs | Complete `ALU8.OP` |
| --- | --- | --- | --- | --- |
| `0b000` | `EQ` | `0x01` if `E`, otherwise `0x00` | All `DIFF` bits | `0x15` |
| `0b001` | `SLTU` | `0x01` if `L_u`, otherwise `0x00` | `CARRY_IN` | `0x16` |
| `0b010` | `SLT` | `0x01` if `L_s`, otherwise `0x00` | `DIFF[7]`, `OVERFLOW_IN` | `0x17` |
| `0b011` | `MINU` | `A` if `L_u`, otherwise `B` | `CARRY_IN` | `0x18` |
| `0b100` | `MAXU` | `B` if `L_u`, otherwise `A` | `CARRY_IN` | `0x19` |
| `0b101` | `MINS` | `A` if `L_s`, otherwise `B` | `DIFF[7]`, `OVERFLOW_IN` | `0x1A` |
| `0b110` | `MAXS` | `B` if `L_s`, otherwise `A` | `DIFF[7]`, `OVERFLOW_IN` | `0x1B` |
| `0b111` | Reserved | `0x00` | None | No corresponding comparison operation |

Predicate operations ignore the `A` and `B` pins directly; the supplied subtraction signals determine the decision. Min/max operations additionally use the original operands as output data. Inputs absent from an operation's decision and data paths are ignored for a known local opcode. Equal operands select `B` for min and `A` for max, with identical output values.

The component does not validate the consistency requirement. For example, `EQ` returns `0x01` for `DIFF = 0` even if the separately supplied `A` and `B` differ. The complete ALU prevents this mismatch by wiring all subtraction signals from the shared arithmetic path.

The global codes `0x15`–`0x1B` are explicitly remapped to local codes `0`–`6`. Passing only the low three global opcode bits would select the wrong operation. The complete ALU computes result flags separately; a false predicate produces `OUT = 0`, so its result-zero flag is 1.

#### C++ example

```cpp
std::uint8_t compare_select8_ref(
    std::uint8_t a, std::uint8_t b, std::uint8_t diff,
    bool carry_in, bool overflow_in, std::uint8_t op) {
    const bool equal = zero_detect8_ref(diff);
    const bool unsigned_lt = !carry_in;
    const bool signed_lt = ((diff & 0x80u) != 0) != overflow_in;
    switch (op) {
    case 0: return static_cast<std::uint8_t>(equal);
    case 1: return static_cast<std::uint8_t>(unsigned_lt);
    case 2: return static_cast<std::uint8_t>(signed_lt);
    case 3: return unsigned_lt ? a : b;
    case 4: return unsigned_lt ? b : a;
    case 5: return signed_lt ? a : b;
    case 6: return signed_lt ? b : a;
    default: return 0;
    }
}
```

The example consumes `diff`, carry, and overflow rather than recomputing `a - b`. Like the structural component, it does not reject inconsistent input combinations. `op` represents the three-bit local selector; out-of-range integer arguments also return zero.

#### Unknown inputs and timing

For a known `EQ` selection, the `ZeroDetect8` rules apply to `DIFF`. A known 1 in `DIFF` establishes inequality even if another bit is unknown. For `SLTU`, unknown carry makes the predicate bit unknown. For `SLT`, an unknown sign or overflow input makes the predicate bit unknown. In each predicate operation, output bits 7–1 remain zero.

Min/max outputs follow the structural multiplexers, including their handling of an unknown decision signal; they do not perform a separate integer comparison to resolve it. The known reserved local selection produces zero even with unknown data. `Z` inputs passing through logic are treated as unknown.

When used with the arithmetic unit, subtraction data and flags can arrive at different times before the comparison settles. There is no single declared structural `CompareSelect8` latency. The standalone recorded scenario supplies `DIFF` and the flags as inputs; it does not simulate the upstream subtraction's propagation.

### Implementation

#### Structural implementation

| Internal block | Function |
| --- | --- |
| `DIFF_SPLIT` | Expose `DIFF[7]` for the signed decision |
| `EQUAL` (`ZeroDetect8`) | Derive the equality predicate from `DIFF` |
| `UNSIGNED_LT` (`NOTGate`) | Invert the no-borrow input |
| `SIGNED_LT` (`XORGate`) | Combine the difference sign and overflow |
| `A_SPLIT`, `B_SPLIT` | Expose original operand bits for selection |
| `MINU_*`, `MAXU_*`, `MINS_*`, `MAXS_*` | Select operand bits using `Mux2to1` components |
| `RESULT_*` (`Mux8to1`) | Select a predicate, min/max data, or constant zero per output bit |
| `OUT_JOIN` | Assemble the result word |

To connect a standalone [AddSub8](2.1.md), drive its `A` and `B` from the same operands, set `SUB = 1` and `C_IN = 1`, and connect:

| Subtraction output | `CompareSelect8` input |
| --- | --- |
| `AddSub8.OUT` | `DIFF` |
| `AddSub8.CARRY_OUT` | `CARRY_IN` |
| `AddSub8.OVERFLOW` | `OVERFLOW_IN` |

The complete ALU uses `ArithmeticUnit8` in `SUB` mode for these signals and selects the `CompareSelect8` result. No second `Adder8` or dedicated comparator datapath is instantiated for these operations.

#### Behavioral implementation

`Behavioral8<CompareSelect8>` calls `compare`. It derives equality from `DIFF`, unsigned less-than from `CARRY_IN`, and signed less-than from `DIFF[7] XOR OVERFLOW_IN`, then uses four-state multiplexer functions to assemble the selected predicate or operand. It consumes the supplied subtraction signals without recomputing or validating `A - B`.

The evaluator is defined in [ALU8Behavioral.cpp](https://github.com/arnold518/reinventing-the-wheel/blob/github-pages/src/modules/composite/ALU8Behavioral.cpp); its value functions are in [ALU8ValueModel.hpp](https://github.com/arnold518/reinventing-the-wheel/blob/github-pages/src/modules/composite/ALU8ValueModel.hpp). It retains the public pins and schedules outputs with one abstract delay tick, without internal circuit objects or gate-propagation glitches.

The recorded scenario runs against both implementations in CTest. [ALU8FidelityContractTest](https://github.com/arnold518/reinventing-the-wheel/blob/github-pages/src/tests/ALU8BehavioralTests.cpp) checks binary/X/Z settled-output equivalence against the structural circuit. The example table uses the default structural run; its checkpoint times need not match the behavioral run.
