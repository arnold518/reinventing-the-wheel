# § 2.2. Logic Operations

`LogicUnit8` provides the seven bitwise operations of `ALU8`. This page specifies the standalone component; its local operation selector is not the complete ALU's five-bit opcode.

| Component | Description | Structural | Behavioral |
| --- | --- | :---: | :---: |
| `LogicUnit8` | Selects an eight-bit AND, OR, XOR, NOT, NAND, NOR, or XNOR result | Yes | Yes |

These columns indicate registered simulator implementations; the simplified C++ examples below are not counted.

The bit numbering and combinational conventions from [2.1. Arithmetic Components](2.1.md) apply here. The simplified **C++ example** describes binary behavior, not the simulator implementation; it omits propagation delays and `X`/`Z` handling.

## 2.2.1. `LogicUnit8`

`LogicUnit8` computes bitwise results from two eight-bit operands and selects one result for `OUT`. It has no carry input, flags, or stored state.

### IO pins

| Pin | Direction | Width | Description |
| --- | --- | ---: | --- |
| `A` | Input | 8 | First operand; the only operand used by `NOT` |
| `B` | Input | 8 | Second operand; ignored by `NOT` and the reserved selection |
| `OP` | Input | 3 | Local logic operation selector |
| `OUT` | Output | 8 | Selected bitwise result |

### Behavior

Each output bit depends on the corresponding operand bits. There is no carry propagation between bit positions. Complements are restricted to eight bits; these are bitwise operations, not logical operations on whole-word truth values.

| Local `OP` | Operation | `OUT` | Uses `B`? | Complete `ALU8.OP` |
| --- | --- | --- | --- | --- |
| `0b000` | `AND` | `A & B` | Yes | `0x08` |
| `0b001` | `OR` | `A \| B` | Yes | `0x09` |
| `0b010` | `XOR` | `A ^ B` | Yes | `0x0A` |
| `0b011` | `NOT` | `(~A) & 0xFF` | No | `0x0B` |
| `0b100` | `NAND` | `(~(A & B)) & 0xFF` | Yes | `0x0C` |
| `0b101` | `NOR` | `(~(A \| B)) & 0xFF` | Yes | `0x0D` |
| `0b110` | `XNOR` | `(~(A ^ B)) & 0xFF` | Yes | `0x0E` |
| `0b111` | Reserved | `0x00`, independently of `A` and `B` | No | `0x0F` is reserved |

The standalone component has no `INVALID_OP` output. Its reserved selection returns zero; the complete ALU separately reports reserved global encodings through `INVALID_OP`. The complete ALU also derives `ZERO` and `NEGATIVE` from the selected result and clears `CARRY` and `OVERFLOW` for logic operations.

#### C++ example

```cpp
#include <cstdint>

std::uint8_t logic8_ref(
    std::uint8_t a, std::uint8_t b, std::uint8_t op) {
    const unsigned x = a, y = b;
    unsigned result;
    switch (op) {
    case 0: result = x & y; break;
    case 1: result = x | y; break;
    case 2: result = x ^ y; break;
    case 3: result = ~x; break;
    case 4: result = ~(x & y); break;
    case 5: result = ~(x | y); break;
    case 6: result = ~(x ^ y); break;
    default: result = 0; break;
    }
    return static_cast<std::uint8_t>(result & 0xFFu);
}
```

`op` represents the three-bit local selector. Out-of-range integer arguments also return zero, although they cannot occur on a three-bit binary pin.

#### Unknown inputs and timing

For a known `OP`, the gates retain bit-level four-state behavior:

- `0 AND X = 0` and `1 OR X = 1`; a controlling operand can determine an output despite an unknown input.
- XOR and inversion produce `X` when their relevant input is unknown. `Z` inputs are treated as unknown logic by these gates, not forwarded as high impedance.
- `NOT` ignores `B`, including `X` or `Z` values. The known reserved selection returns zero even when either operand is unknown.

An unknown selector follows the structural multiplexer gates; it is not interpreted as the reserved binary code. The C++ example cannot represent these states.

Operand or opcode changes propagate through gates and multiplexers. Different result bits can settle at different times; there is no single declared component latency. The tables specify settled outputs.

### Implementation

#### Structural implementation

| Internal component | Count | Function |
| --- | ---: | --- |
| `BitSplitter<8>` | 2 | Expose the individual bits of `A` and `B` |
| `ANDGate`, `ORGate`, `XORGate` | 8 each | Compute the three binary operations, one gate per bit |
| `NOTGate` | 32 | Invert `A` and the three binary results for `NOT`, `NAND`, `NOR`, and `XNOR` |
| `Mux8to1` | 8 | Select one of seven results or constant zero for each bit |
| `ConstantValue<1>` | 1 | Supply the reserved selection's zero |
| `BitJoiner<8>` | 1 | Assemble the selected bits into `OUT` |

These counts describe direct children of `LogicUnit8`; the multiplexers contain additional gates. `NAND`, `NOR`, and `XNOR` reuse the corresponding non-inverted result and a `NOTGate`, rather than instantiate separate eight-bit operation modules.

#### Behavioral implementation

`Behavioral8<LogicUnit8>` calls `logic`. For each bit, it computes the AND, OR, XOR, and inverted candidates, then selects one through a four-state eight-way multiplexer function. The reserved input is constant zero. Unknown selectors follow the multiplexer expressions, not a binary `switch`.

The evaluator is defined in [ALU8Behavioral.cpp](https://github.com/arnold518/reinventing-the-wheel/blob/github-pages/src/modules/composite/ALU8Behavioral.cpp); its value functions are in [ALU8ValueModel.hpp](https://github.com/arnold518/reinventing-the-wheel/blob/github-pages/src/modules/composite/ALU8ValueModel.hpp). It retains the public pins without functional circuit children. Catalog construction supplies a delay table characterized from the gates; where a delay twin is available and agrees with the computed value, publication can follow the current inputs’ gate-level settling time within that bound, subject to older pending results. The compact evaluator does not reproduce transient gate glitches.

The recorded scenario runs against both implementations in CTest. [ALU8FidelityContractTest](https://github.com/arnold518/reinventing-the-wheel/blob/github-pages/src/tests/ALU8BehavioralTests.cpp) checks binary/X/Z settled-output equivalence against the structural circuit. The example table uses the default structural run; its checkpoint times need not match the behavioral run.
