# § 2.6. Complete ALU8

`ALU8` combines the arithmetic, logic, shift/rotate, comparison/select, and flag components into one eight-bit combinational unit. It supports 29 operations, a five-bit opcode, and an explicit carry input. Multiplication and division are not included.

| Component | Description | Structural | Behavioral |
| --- | --- | :---: | :---: |
| `ALU8ControlDecoder` | Decodes the five-bit opcode into local operation selectors, result-source enables, and an invalid-opcode flag | Yes | Yes |
| `ALU8ResultSelector` | Combines six enabled result sources into the final eight-bit result | Yes | Yes |
| `ALU8` | Integrates the operation units, control decoder, result selector, and flags behind one input/output interface | Yes | Yes |

These columns indicate registered simulator implementations; the simplified C++ examples below are not counted.

The simplified **C++ examples** describe binary behavior, not the simulator implementation; they omit propagation delays and `X`/`Z` handling. The complete ALU example uses the functions from §§2.1–2.5.

## 2.6.1. `ALU8ControlDecoder`

This block translates the complete ALU opcode into local selectors and result/flag enables. It does not compute operand data.

### IO pins

| Pin | Direction | Width | Description |
| --- | --- | ---: | --- |
| `OP` | Input | 5 | Complete ALU opcode |
| `LOCAL_OP` | Output | 3 | `OP[2:0]`, used by logic and shift units |
| `ARITH_OP` | Output | 3 | Arithmetic selector; forced to local `SUB = 2` during comparisons |
| `COMPARE_OP` | Output | 3 | Comparison selector, 0–6 for global opcodes 21–27; otherwise 0 |
| `ARITHMETIC_ENABLE`, `LOGIC_ENABLE`, `SHIFT_ENABLE`, `COMPARE_ENABLE` | Output | 1 each | Enable the corresponding result source |
| `PASS_A_ENABLE`, `PASS_B_ENABLE` | Output | 1 each | Enable operand pass-through |
| `INVALID_OP` | Output | 1 | Reserved opcode indication |

### Behavior

For binary `OP`, arithmetic is enabled for 0–6, logic for 8–14, shifts for 16–20, comparisons for 21–27, and operand pass-through for 28 or 29. At most one result enable is high. `CLEAR = 30` and reserved encodings 7, 15, 31 disable every result source; only the reserved encodings set `INVALID_OP`.

During comparisons, `ARITH_OP = 2` requests the shared subtraction, but `ARITHMETIC_ENABLE = 0`: its intermediate result and flags must not be exposed as the final ALU result and flags. Outside comparisons, `ARITH_OP = OP[2:0]`. Unused local selectors are not forced to zero except `COMPARE_OP`.

#### C++ example

```cpp
#include <cstdint>
#include <stdexcept>

struct ALU8Control {
    std::uint8_t LOCAL_OP, ARITH_OP, COMPARE_OP;
    bool ARITHMETIC_ENABLE, LOGIC_ENABLE, SHIFT_ENABLE, COMPARE_ENABLE;
    bool PASS_A_ENABLE, PASS_B_ENABLE, INVALID_OP;
};

ALU8Control alu8_control_ref(std::uint8_t op) {
    if (op > 31) throw std::invalid_argument("OP must fit five bits");
    const bool compare = op >= 21 && op <= 27;
    return {
        static_cast<std::uint8_t>(op & 7),
        static_cast<std::uint8_t>(compare ? 2 : op & 7),
        static_cast<std::uint8_t>(compare ? op - 21 : 0),
        op <= 6, op >= 8 && op <= 14, op >= 16 && op <= 20, compare,
        op == 28, op == 29, op == 7 || op == 15 || op == 31
    };
}
```

#### Unknown inputs and timing

Unknown opcode bits follow the decoder and gates. `INVALID_OP` does not indicate whether all input bits are binary. The block has no clock or stored state; control outputs can change at different propagation times.

### Implementation

#### Structural implementation

`OPERATION_DECODER` is a `Decoder5to32` with its enable tied high. OR networks combine decoded lines into group enables and the invalid flag. A splitter/joiner forwards the low three bits; three `Mux2to1` gates override the arithmetic selector during comparisons. OR networks remap comparison opcodes to local selectors.

#### Behavioral implementation

`Behavioral8<ALU8ControlDecoder>` calls `control`. It evaluates all 32 opcode matches with four-state logic, combines them into group enables and `INVALID_OP`, and constructs the local selectors. `LOCAL_OP` directly copies `OP[2:0]`, preserving `Z` as wiring does; the other outputs pass through logic expressions.

The evaluator is defined in [ALU8Behavioral.cpp](https://github.com/arnold518/reinventing-the-wheel/blob/github-pages/src/modules/composite/ALU8Behavioral.cpp); its value functions are in [ALU8ValueModel.hpp](https://github.com/arnold518/reinventing-the-wheel/blob/github-pages/src/modules/composite/ALU8ValueModel.hpp). It retains the public pins without functional circuit children. Catalog construction supplies a delay table characterized from the gates; where a delay twin is available and agrees with the computed value, publication can follow the current inputs’ gate-level settling time within that bound, subject to older pending results. The compact evaluator does not reproduce transient gate glitches.

The recorded scenario runs against both implementations in CTest. [ALU8FidelityContractTest](https://github.com/arnold518/reinventing-the-wheel/blob/github-pages/src/tests/ALU8BehavioralTests.cpp) checks binary/X/Z settled-output equivalence against the structural circuit. The example table uses the default structural run; its checkpoint times need not match the behavioral run.

## 2.6.2. `ALU8ResultSelector`

This block combines six enabled data sources into one result bus. Its enable pins are independent; it is not a priority selector.

### IO pins

| Pin | Direction | Width | Description |
| --- | --- | ---: | --- |
| `ARITHMETIC_RESULT`, `LOGIC_RESULT`, `SHIFT_RESULT`, `COMPARE_RESULT` | Input | 8 each | Results from the operation units |
| `A`, `B` | Input | 8 each | Operand pass-through sources |
| `ARITHMETIC_ENABLE`, `LOGIC_ENABLE`, `SHIFT_ENABLE`, `COMPARE_ENABLE` | Input | 1 each | Enable the corresponding unit result |
| `PASS_A_ENABLE`, `PASS_B_ENABLE` | Input | 1 each | Enable operand pass-through |
| `OUT` | Output | 8 | Bitwise OR of the enabled sources |

### Behavior

Each source is AND-masked by its enable, then the six masked words are OR-combined. With one enable high, `OUT` is that source. With all enables low, `OUT = 0`. Multiple enables produce the bitwise OR of those sources, not an error or a priority choice. The integrated decoder only generates zero-hot or one-hot enables for binary opcodes.

#### C++ example

The arrays use this order: arithmetic, logic, shift, comparison, A, B.

```cpp
#include <array>
#include <cstdint>

std::uint8_t alu8_result_selector_ref(
    const std::array<std::uint8_t, 6>& sources,
    const std::array<bool, 6>& enables) {
    std::uint8_t out = 0;
    for (unsigned i = 0; i < sources.size(); ++i)
        if (enables[i]) out |= sources[i];
    return out;
}
```

#### Unknown inputs and timing

A low enable masks `X`/`Z` data. Active unknown data follows AND/OR gate rules; high impedance is not forwarded as high impedance through these gates. Unknown enables also follow gate rules rather than selecting an arbitrary input. There is no stored state or fixed cycle latency.

### Implementation

#### Structural implementation

Six eight-bit splitters feed 48 AND gates, followed by 40 OR gates and one output joiner. No operation unit is clock-gated or stopped by these enables.

#### Behavioral implementation

`Behavioral8<ALU8ResultSelector>` calls `select`. For each output bit, it AND-masks each of the six source bits with its enable and OR-combines the contributions using four-state logic. Multiple enabled sources are combined, not prioritized; disabled unknown data is masked to zero.

The evaluator is defined in [ALU8Behavioral.cpp](https://github.com/arnold518/reinventing-the-wheel/blob/github-pages/src/modules/composite/ALU8Behavioral.cpp); its value functions are in [ALU8ValueModel.hpp](https://github.com/arnold518/reinventing-the-wheel/blob/github-pages/src/modules/composite/ALU8ValueModel.hpp). It retains the public pins without functional circuit children. Catalog construction supplies a delay table characterized from the gates; where a delay twin is available and agrees with the computed value, publication can follow the current inputs’ gate-level settling time within that bound, subject to older pending results. The compact evaluator does not reproduce transient gate glitches.

The recorded scenario runs against both implementations in CTest. [ALU8FidelityContractTest](https://github.com/arnold518/reinventing-the-wheel/blob/github-pages/src/tests/ALU8BehavioralTests.cpp) checks binary/X/Z settled-output equivalence against the structural circuit. The example table uses the default structural run; its checkpoint times need not match the behavioral run.

## 2.6.3. `ALU8`

The caller supplies operands, an operation, and carry input. Opcode decoding, shared subtraction for comparisons, result selection, and flag selection are internal.

### IO pins

| Pin | Direction | Width | Description |
| --- | --- | ---: | --- |
| `A` | Input | 8 | First operand |
| `B` | Input | 8 | Second operand or shift/rotate distance |
| `OP` | Input | 5 | Complete ALU opcode |
| `C_IN` | Input | 1 | Carry/no-borrow input for `ADC`/`SBC`; carry source for zero-distance shifts/rotates |
| `OUT` | Output | 8 | Selected result |
| `ZERO` | Output | 1 | 1 when `OUT` is zero |
| `NEGATIVE` | Output | 1 | Bit 7 of a binary `OUT` |
| `CARRY` | Output | 1 | Arithmetic carry/no-borrow or shift/rotate carry; otherwise 0 |
| `OVERFLOW` | Output | 1 | Signed arithmetic overflow; otherwise 0 |
| `INVALID_OP` | Output | 1 | A reserved opcode is selected |

There is no clock, start, busy, valid/ready handshake, or stored status register. `DIFF`, `CARRY_IN`, and `OVERFLOW_IN` from [CompareSelect8](2.4.md#242-compareselect8) are not external ALU pins.

### Behavior

Operands and `OUT` are eight-bit patterns. Arithmetic wraps modulo 256; signed operations interpret a pattern as two's complement in −128–127. Let $s(x)$ denote that signed interpretation and $n=B\mathbin{\&}7$ the effective shift distance.

#### Opcode map

| `OP` | Operation | `OUT` |
| --- | --- | --- |
| `0x00` | `ADD` | `A + B` |
| `0x01` | `ADC` | `A + B + C_IN` |
| `0x02` | `SUB` | `A - B` |
| `0x03` | `SBC` | `A - B - (1 - C_IN)` |
| `0x04` | `INC` | `A + 1` |
| `0x05` | `DEC` | `A - 1` |
| `0x06` | `NEG` | `0 - A` |
| `0x07` | Reserved | `0x00`; `INVALID_OP = 1` |
| `0x08` | `AND` | `A AND B`, bitwise |
| `0x09` | `OR` | `A OR B`, bitwise |
| `0x0A` | `XOR` | `A XOR B`, bitwise |
| `0x0B` | `NOT` | Bitwise complement of `A` |
| `0x0C` | `NAND` | Bitwise complement of `A AND B` |
| `0x0D` | `NOR` | Bitwise complement of `A OR B` |
| `0x0E` | `XNOR` | Bitwise complement of `A XOR B` |
| `0x0F` | Reserved | `0x00`; `INVALID_OP = 1` |
| `0x10` | `SLL` | Shift `A` left by `n`, zero fill |
| `0x11` | `SRL` | Shift `A` right by `n`, zero fill |
| `0x12` | `SRA` | Shift `A` right by `n`, sign fill |
| `0x13` | `ROL` | Rotate `A` left by `n` |
| `0x14` | `ROR` | Rotate `A` right by `n` |
| `0x15` | `EQ` | `0x01` if `A == B`, otherwise `0x00` |
| `0x16` | `SLTU` | `0x01` if unsigned `A < B`, otherwise `0x00` |
| `0x17` | `SLT` | `0x01` if `s(A) < s(B)`, otherwise `0x00` |
| `0x18` | `MINU` | Smaller unsigned operand |
| `0x19` | `MAXU` | Larger unsigned operand |
| `0x1A` | `MINS` | Operand with smaller signed value |
| `0x1B` | `MAXS` | Operand with larger signed value |
| `0x1C` | `PASS_A` | `A` |
| `0x1D` | `PASS_B` | `B` |
| `0x1E` | `CLEAR` | `0x00`; `INVALID_OP = 0` |
| `0x1F` | Reserved | `0x00`; `INVALID_OP = 1` |

Min/max operations return the original operand pattern, not a predicate or magnitude. Rotations operate on eight bits, not on a nine-bit word containing carry. The full operation details are in [arithmetic](2.1.md), [logic](2.2.md), [shifts and rotations](2.3.md), and [comparison and selection](2.4.md).

#### Flags and ignored inputs

`ZERO = [OUT == 0]` and `NEGATIVE = OUT[7]` for every binary result, including predicates and reserved operations. A false comparison therefore sets `ZERO = 1`; a true comparison returns `0x01` and sets `ZERO = 0`.

| Operation group | `CARRY` | `OVERFLOW` |
| --- | --- | --- |
| Arithmetic (`0x00`–`0x06`) | Carry-out for addition; 1 means **no borrow** for subtraction | Signed result before wrapping is outside −128–127 |
| Shift/rotate (`0x10`–`0x14`), `n > 0` | Last bit shifted/rotated out | 0 |
| Shift/rotate (`0x10`–`0x14`), `n = 0` | `C_IN` | 0 |
| Logic, comparison, min/max, pass, clear, reserved | 0 | 0 |

The arithmetic flag rules for `INC`, `DEC`, and `NEG` are specified in [2.1](2.1.md#arithmetic-flags). In particular, `NEG` sets carry only for `A = 0`; this ALU uses the no-borrow convention consistently.

For known opcodes, ignored inputs are isolated from the settled outputs:

- `B` is ignored by `INC`, `DEC`, `NEG`, `NOT`, and `PASS_A`.
- `A` is ignored by `PASS_B`; both operands are ignored by `CLEAR` and reserved operations.
- Shifts and rotations ignore `B[7:3]`, even when those bits are unknown.
- `C_IN` is used only by `ADC`, `SBC`, and zero-distance shifts/rotates. In particular, ordinary subtraction and all comparisons ignore it.

Reserved opcodes produce `OUT = 0`, `ZERO = 1`, `NEGATIVE = CARRY = OVERFLOW = 0`, and `INVALID_OP = 1`. `CLEAR` produces the same result and flags except `INVALID_OP = 0`. For a supported, known opcode, `INVALID_OP = 0` even when an operand is unknown or arithmetic overflows.

#### C++ example

This example composes the functions from [2.1](2.1.md), [2.2](2.2.md), [2.3](2.3.md), [2.4](2.4.md), and [2.5](2.5.md). Compile those C++ examples first, in chapter order.

```cpp
struct ALU8Result {
    std::uint8_t OUT;
    bool ZERO;
    bool NEGATIVE;
    bool CARRY;
    bool OVERFLOW;
    bool INVALID_OP;
};

ALU8Result alu8_ref(
    std::uint8_t a, std::uint8_t b, std::uint8_t op, bool c_in) {
    const bool arithmetic = op <= 0x06;
    const bool logic = op >= 0x08 && op <= 0x0E;
    const bool shift = op >= 0x10 && op <= 0x14;
    const bool comparison = op >= 0x15 && op <= 0x1B;
    const bool transfer = op >= 0x1C && op <= 0x1E;
    const bool invalid = !(arithmetic || logic || shift || comparison || transfer);

    std::uint8_t out = 0;
    bool arith_carry = false, arith_overflow = false, shift_carry = false;
    if (arithmetic || comparison) {
        const auto local_op = static_cast<std::uint8_t>(comparison ? 2 : op);
        const auto r = arithmetic8_ref(a, b, local_op, c_in);
        arith_carry = r.CARRY;
        arith_overflow = r.OVERFLOW;
        out = comparison
            ? compare_select8_ref(a, b, r.OUT, r.CARRY, r.OVERFLOW,
                                  static_cast<std::uint8_t>(op - 0x15))
            : r.OUT;
    } else if (logic) {
        out = logic8_ref(a, b, static_cast<std::uint8_t>(op - 0x08));
    } else if (shift) {
        const auto r = shift8_ref(a, b, static_cast<std::uint8_t>(op - 0x10), c_in);
        out = r.OUT;
        shift_carry = r.CARRY;
    } else if (op == 0x1C) {
        out = a;
    } else if (op == 0x1D) {
        out = b;
    }
    const auto f = flags8_ref(out, arithmetic, shift,
                              arith_carry, arith_overflow, shift_carry);
    return {out, f.ZERO, f.NEGATIVE, f.CARRY, f.OVERFLOW, invalid};
}
```

`op` represents a five-bit binary pin. Out-of-range integer arguments also return the invalid-operation result; they are not masked into an unrelated valid opcode. The example skips inactive computations for clarity, whereas the structural circuit can evaluate them and masks their outputs.

#### Unknown inputs and timing

The structural gates determine four-state behavior; the C++ example does not. Known operation selection masks inactive result paths, so unknown data in an unused path does not automatically make `OUT` unknown. For example, `CLEAR` and reserved opcodes still produce their defined zero result with unknown data and carry inputs, and `AND` with an all-zero operand produces zero despite unknown bits in the other operand.

An `X`/`Z` bit that affects the selected computation follows its gates' propagation rules. `ZERO` can be unknown for a partially unknown result with no known 1. A high-impedance operand bit passing through logic is treated as unknown, not preserved as a high-impedance output.

An opcode containing `X` or `Z` is not automatically a reserved encoding. Decoder and selection gates determine the outputs; `INVALID_OP` is not an input-validity checker. The contract test specifically checks that an entirely unknown/high-impedance opcode produces `INVALID_OP = X`, without asserting a complete output word for that case.

In structural fidelity, all operation paths are combinational and may change while gates settle. There is no fixed instruction-cycle count, atomic result/flag update, or declared worst-case structural `ALU8` latency. Recorded checkpoints inspect settled results; intermediate timeline positions can show propagation through the decoder, carry chain, result selector, and flags. Catalog-selected behavioral fidelity uses delays characterized from the gate network. Its delay twin can time the current operation and operands, while the proven per-path table bounds publication when the twin cannot answer. It does not reproduce intermediate gate glitches.

### Implementation

#### Structural implementation

| Internal component or network | Responsibility |
| --- | --- |
| `CONTROL` (`ALU8ControlDecoder`) | Decode the opcode into local selectors, enables, and the invalid flag |
| `ARITHMETIC` (`ArithmeticUnit8`) | Seven arithmetic operations and shared subtraction for comparisons |
| `LOGIC` (`LogicUnit8`) | Seven bitwise operations |
| `SHIFTER` (`BarrelShifter8`) | Three shifts and two rotations |
| `COMPARE_SELECT` (`CompareSelect8`) | Interpret subtraction data/flags and select predicates or operands |
| `RESULT_SELECT` (`ALU8ResultSelector`) | Select and assemble the final eight-bit word |
| `FLAGS` (`ALU8FlagUnit`) | Derive zero/sign and select carry/overflow |

In the default structural profile there is exactly one `AddSub8`, containing one `Adder8` and eight `FullAdder` components, in the complete ALU hierarchy. Each of the seven operation units can independently switch between structural and behavioral fidelity. Nested `AddSub8`, `Adder8`, and `ZeroDetect8` units are also selectable. A structural root with all seven units set to behavioral has eight components; a behavioral root has one. `Structural8Builder` is only a construction/wiring helper.

The five-bit opcode is translated to each unit's three-bit local selector:

| Selected group | Local operation | Result source |
| --- | --- | --- |
| Arithmetic | `OP[2:0]` | `ARITHMETIC.OUT` |
| Logic | `OP[2:0]` | `LOGIC.OUT` |
| Shift/rotate | `OP[2:0]` | `SHIFTER.OUT` |
| Comparison/min/max | Arithmetic forced to local `SUB = 2`; comparison remapped to `OP - 0x15` | `COMPARE_SELECT.OUT` |
| `PASS_A`, `PASS_B` | No unit result selected | External `A` or `B` |
| `CLEAR`, reserved | No result source enabled | Zero from the masked result network |

For comparison operations, the same `A` and `B` drive both units. `ARITHMETIC.OUT`, `CARRY`, and `OVERFLOW` connect to `COMPARE_SELECT.DIFF`, `CARRY_IN`, and `OVERFLOW_IN`. This makes the comparison inputs consistent without requiring the caller to calculate them or adding a second subtractor. The arithmetic **result/flag enable** remains low during comparisons, even though the arithmetic unit is computing their intermediate subtraction.

The result network has six sources: arithmetic, logic, shift, comparison, `A`, and `B`. For each output bit, six AND gates mask these sources with decoded enables and five OR gates combine them. These enables select outputs; they do not stop inactive units from evaluating. The selected result feeds both `OUT` and `FLAGS.RESULT`. The top-level invalid flag comes from its own five-bit decoder, not from the arithmetic unit's local `INVALID_OP`.

#### Behavioral implementation

`Behavioral8<ALU8>` calls `alu`, which composes the four-state control, arithmetic, logic, shift, comparison, result-selection, and flag functions. Comparison inputs come from the same computed subtraction result and flags. Unlike the simplified C++ example, this evaluator computes the operation paths and masks their outputs, preserving the gate expressions' treatment of inactive and unknown inputs.

The evaluator is defined in [ALU8Behavioral.cpp](https://github.com/arnold518/reinventing-the-wheel/blob/github-pages/src/modules/composite/ALU8Behavioral.cpp); its value functions are in [ALU8ValueModel.hpp](https://github.com/arnold518/reinventing-the-wheel/blob/github-pages/src/modules/composite/ALU8ValueModel.hpp). It retains the public pins without functional circuit children. Catalog construction supplies a delay table characterized from the gates; where a delay twin is available and agrees with the computed value, publication can follow the current inputs’ gate-level settling time within that bound, subject to older pending results. The compact evaluator does not reproduce transient gate glitches.

The recorded scenario runs against both implementations in CTest. [ALU8FidelityContractTest](https://github.com/arnold518/reinventing-the-wheel/blob/github-pages/src/tests/ALU8BehavioralTests.cpp) checks binary/X/Z settled-output equivalence against the structural circuit. The example table uses the default structural run; its checkpoint times need not match the behavioral run.
