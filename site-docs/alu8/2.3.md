# § 2.3. Shifts and Rotations

`BarrelShifter8` provides variable-distance shifts and rotations for `ALU8`. It operates on eight-bit words and reports the last shifted-out bit separately from the result.

| Component | Description |
| --- | --- |
| `BarrelShifter8` | Shifts or rotates an eight-bit word by zero through seven positions and reports the carry/last shifted-out bit |

The combinational and bit-numbering conventions from [2.1. Arithmetic Components](2.1.md) apply here. The C++ function below is a binary-input behavioral reference, not a registered behavioral simulator component.

## 2.3.1. `BarrelShifter8`

`BarrelShifter8` selects a shift or rotation of `A` by zero through seven bit positions. The result is produced by a structural multiplexer network, not by a clocked sequence of shifts.

### IO pins

| Pin | Direction | Width | Description |
| --- | --- | ---: | --- |
| `A` | Input | 8 | Word to shift or rotate |
| `B` | Input | 8 | Shift distance in bits 2–0; bits 7–3 are ignored |
| `OP` | Input | 3 | Local shift/rotation selector |
| `C_IN` | Input | 1 | Carry value returned for a valid operation with distance zero |
| `OUT` | Output | 8 | Shifted or rotated word |
| `CARRY` | Output | 1 | Last shifted-out bit, or `C_IN` for distance zero |

There are no `OVERFLOW`, `ZERO`, `NEGATIVE`, or `INVALID_OP` pins on this component.

### Behavior

The effective distance is

$$
n = B \mathbin{\&} 7, \qquad 0 \leq n \leq 7.
$$

Thus `B = 0x08` means distance zero, not a shift by eight; `B = 0xFF` means distance seven.

| Local `OP` | Operation | Movement and fill | Complete `ALU8.OP` |
| --- | --- | --- | --- |
| `0b000` | `SLL` | Shift left; fill low bits with zero | `0x10` |
| `0b001` | `SRL` | Shift right; fill high bits with zero | `0x11` |
| `0b010` | `SRA` | Shift right; fill high bits with the original `A[7]` | `0x12` |
| `0b011` | `ROL` | Rotate left; wrap shifted-out high bits into low positions | `0x13` |
| `0b100` | `ROR` | Rotate right; wrap shifted-out low bits into high positions | `0x14` |
| `0b101`–`0b111` | Reserved | `OUT = 0`, `CARRY = 0`, regardless of other inputs | No corresponding shift operation |

The reserved local selections are not a global invalid-opcode table: global codes `0x15`–`0x17` select comparison operations in the complete ALU. The top-level decoder determines which subunit's output is used.

For every valid operation at `n = 0`, `OUT = A` and `CARRY = C_IN`. For `1 ≤ n ≤ 7`, the low eight result bits are

$$
\begin{aligned}
\mathrm{SLL}(A,n) &= (A\,2^n) \bmod 256, \\
\mathrm{SRL}(A,n) &= \left\lfloor A/2^n \right\rfloor, \\
\mathrm{SRA}(A,n) &= \left\lfloor s(A)/2^n \right\rfloor \bmod 256.
\end{aligned}
$$

Here $s(A)$ is the two's-complement interpretation from 2.1. For negative operands, arithmetic right shift rounds toward negative infinity; it is not C++ signed division's truncation toward zero.

#### Carry and ignored inputs

| Operation | `CARRY` when `n > 0` |
| --- | --- |
| `SLL`, `ROL` | Original `A[8 - n]` |
| `SRL`, `SRA`, `ROR` | Original `A[n - 1]` |

`C_IN` does not supply a fill bit and never enters `OUT`. For nonzero distance it is ignored, including by the rotations. `ROL` and `ROR` rotate eight bits, not a nine-bit word containing carry. These carry rules report the last bit shifted out, not whether any discarded bit was 1.

#### Unknown inputs and timing

For known, valid `OP` and known `B[2:0]`, the unused upper bits of `B` do not affect either output, even when they contain `X` or `Z`. At nonzero distance, unknown `C_IN` is also isolated. At distance zero, an `X` or `Z` carry input yields `CARRY = X` through the gate network, while known `A` remains unchanged on `OUT`.

Unknown data or relevant control bits follow the underlying multiplexer gates. Bits that are known to be zero-filled can still be determined; a `Z` passing through logic becomes `X`, not a high-impedance output. Known reserved local selections mask both outputs to zero.

The three structural shift stages are combinational, not three clock cycles. Changes pass through direction selection, shift stages, and output masking before settling. No single structural component latency is declared; use the recorded checkpoints to inspect settled data and carry together.

### Implementation

#### Structural implementation

The network first reverses the bit order for leftward operations, uses a shared rightward shift network, and reverses the result back afterward. Reversal changes bit positions; it does not invert their values.

| Internal block | Function |
| --- | --- |
| `A_SPLIT`, `B_SPLIT` | Expose operand bits and distance controls |
| `LEFT_SELECT`, `ROTATE_SELECT`, `ARITHMETIC_SELECT`, `VALID_SELECT` | Derive controls from local `OP` using `Mux8to1` components |
| `INPUT_REVERSE_*` | Select the original or reversed input order |
| `SHIFT_1_*` | Optionally shift by 1, controlled by `B[0]` |
| `SHIFT_2_*` | Optionally shift by 2, controlled by `B[1]` |
| `SHIFT_4_*` | Optionally shift by 4, controlled by `B[2]` |
| `OUTPUT_REVERSE_*` | Restore the bit order for leftward operations |
| `VALID_BIT_*`, `CARRY_VALID` | Mask reserved selections to zero |
| `OUT_JOIN` | Assemble the output word |

Each enabled stage selects either a shifted word or the preceding word. Its carry multiplexer selects the stage's last shifted-out bit when enabled; otherwise it keeps the preceding carry. The chain starts with `C_IN`, which survives only when no shift stage is enabled. Fill selection supplies zero, the sign bit, or wrapped data according to the operation.

#### Binary behavioral reference

```cpp
#include <cstdint>

struct Shift8Result {
    std::uint8_t OUT;
    bool CARRY;
};

Shift8Result shift8_ref(
    std::uint8_t a, std::uint8_t b, std::uint8_t op, bool c_in) {
    if (op > 4) return {0, false};
    const unsigned n = unsigned(b) & 7u;
    if (n == 0) return {a, c_in};

    const unsigned x = a;
    unsigned result = 0;
    switch (op) {
    case 0: result = x << n; break;                     // SLL
    case 1: result = x >> n; break;                     // SRL
    case 2:                                           // SRA
        result = (x >> n) | ((x & 0x80u) ? (0xFFu << (8 - n)) : 0u);
        break;
    case 3: result = (x << n) | (x >> (8 - n)); break;  // ROL
    case 4: result = (x >> n) | (x << (8 - n)); break;  // ROR
    }
    const unsigned carry_bit = (op == 0 || op == 3) ? 8 - n : n - 1;
    return {
        static_cast<std::uint8_t>(result & 0xFFu),
        ((x >> carry_bit) & 1u) != 0,
    };
}
```

The explicit zero-distance branch avoids invalid shift indices. All shifts operate on unsigned integers; sign fill is constructed explicitly. `op` represents the three-bit local selector; out-of-range integer arguments also return zero result and carry.
