## 2026-10-29 — Deliberate limits and evidence-dependent omissions

| Area | Why it is not filled as implemented/proven behavior | Work needed for a stronger claim |
| --- | --- | --- |
| Interrupts, machine-mode trap handling, DMA, live game input, more than two masters per target | Deferred or outside the adopted implementation; polling/terminal traps and the two-port arbiter remain | Separate hardware changes and their contract/integration tests, not additional prose |
| Whole-bus, whole-memory-subsystem and separate M-stage compact models | These roots are structural assemblies; children supply compact forms | No missing whole-root delay table to generate merely for documentation |
| Router/bridge/front-end and whole-device numeric path tables | Parameter-sensitive compiled groups derive delays at build time; there is no canonical stored table for every map/register list | Export a chosen configuration's runtime table and verify it before publishing a numeric map-specific table; do not substitute another topology's table |
| Broad bus correctness, fairness and status precedence | The 400-cycle bus check compares router forms with structural arbitration and unrestricted input changes; it is not an independent legal-traffic transaction model | Protocol driver/reference tests, contention, backpressure, operation/status and burst-rejection cases across supported widths |
| Complete protocol checker | Current flags omit detection of a second accepted request while one is outstanding and burst word counting; directed tests cover only five clean/broken sequences | Checker implementation and negative tests before claiming full port-contract enforcement |
| Generic register-table contract, generated Markdown maps, nonzero RW reset values | No generic per-entry access matrix or site table generator exists. The front end validates the metadata value but does not apply nonzero reset values to RW storage | Generic access/mask/reset/payload tests; generator or maintained consistency check for maps; implement nonzero resets if that metadata contract is required |
| Every accepted memory technology/depth/cache/prediction or checked-link clock | Existing certificates cover a selected panel; `games-machine-checked` is not among `ComputerSystemTimingTest`'s five cases | Certify the exact additional configuration; perform the technology/cache/depth and parameter sweeps before widening timing claims |
| Arbitrary X/Z sequential equivalence and complete width coverage | Known-binary operating boundaries and selected invalid-field tests do not establish arbitrary clock/control behavior. FIFO random/model comparisons cover 8/32, not every width | Focused four-state/width contract cases before expanding the equivalence domain |
| Full native, device/fidelity WASM browser and broader game acceptance | Architecture record reports these gates unrun/incomplete | Full native suite; `RV32IMDeviceBrowserTest`, `DeviceSystemFidelityBrowserTest`, native/WASM execution and remaining repeat/quantum/fidelity/game comparisons |

The default stored timing rows already exist; a hardware delay-table rewrite
or full game recapture is not needed for these documentation edits. The new
runtime-configuration tables and expanded acceptance claims above require
their own evidence and were not fabricated or silently marked complete.
